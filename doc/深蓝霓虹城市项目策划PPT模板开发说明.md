## 4. 视觉规范

### 4.1 视觉方向

- 深夜蓝作为主背景，蓝紫作为远景层次，青色和低饱和绿色作为重点光线。
- 城市楼宇和道路光轨集中在底部、边缘或单侧。
- 标题、正文、指标和业务图片区域保持低干扰。
- 封面和结束页共享城市视觉母题，章节页使用左右方向变化。
- 普通正文不做密集仪表盘、玻璃卡片或发光面板。

### 4.2 设计初值

| 角色 | 色值 |
|---|---|
| 深夜蓝 | `#0B1830` |
| 城市蓝 | `#273957` |
| 青色 | `#47CCD4` |
| 蓝紫 | `#7567BC` |
| 青绿 | `#56BDB5` |

| 浅灰蓝 | `#B8C8DA` |

这些色值是 G3 的设计初值。最终以正式素材、文字可读性和预览结果为准。

### 4.3 画布和排版边界

| 项目 | 规格 |
|---|---|
| 画布 | 1000 × 562.5 |
| 水平安全区 | x = 56～944 |

| 英文和数字 | Arial |
| 正文最小字号 | 16px |

标题过长时先调整版式或分页，不直接截断标题，也不无限缩小字号。

### 5.2 业务图片与固定装饰的区别

- 业务图片使用 `imageType: "content"`，允许替换。
- 背景、纹理、光轨和建筑装饰使用 `imageType: "decoration"`，固定且不可被业务图片替换。
- 普通图标、编号、线条、圆环、进度条和指标数字使用可编辑形状。
- 每项正式素材必须记录来源、尺寸、格式、透明通道、体积和 SHA-256。详细提示词和生成记录放到 QA 目录，不写入主开发说明。

### 5.3 图片生成工具说明

本模板需要的 9 项固定背景和透明装饰图，可以使用 GPT2 图片模板生成，例如可用的 `gpt-image-2` 图片生成能力。9 项素材已通过内置 image_gen 实际生成；工具未暴露模型名称，完整提示词和原始输出记录见素材清单。

- 每项素材必须单独生成，不能把多项素材拼成一张图再切割。
- 生成结果仍需检查文字、Logo、水印、人物、真实品牌、真实地标、尺寸、格式、透明通道、清晰度和实际构图。
- 工具没有暴露实际模型名称时，记录“工具未暴露”，不得猜测或伪造模型名称。
- 每项素材最多生成或重试 3 轮，达到当前规格和实际使用要求后停止。
- GPT2 图片模板只用于 A1～A9 固定装饰，不自动扩展到业务照片、用户内容图或规划外素材。
- 提示词、工具信息、原始输出、最终文件、检查结果和 SHA-256 放在 `doc/assets/template_24_qa/`，不堆入本开发说明。

## 6. 项目接入规则

### 6.1 页面和元素语义

| 对象 | 规则 |
|---|---|
| 页面类型 | 只使用 `cover`、`contents`、`transition`、`content`、`end` |
| 标题 | 使用 `textType: "title"` |
| 普通正文 | 使用 `textType: "content"` 或 `textType: "item"` |
| 项目标题 | 使用 `textType: "itemTitle"` |
| 项目编号 | 使用 `textType: "itemNumber"` 或 `textType: "partNumber"` |
| 业务组 | 标题、正文、编号和业务图使用一致的 `groupId` |
| 固定装饰 | 与业务组隔离，不能因空内容清理被删除 |
| ID | 页面、元素和资源 ID 全部唯一 |

### 6.2 图片和资源

- 生产资源从 `/api/data/` 读取，不写入本机绝对路径。
- 模板 JSON 不嵌入大型 Base64 图片。
- `content` 图片槽必须独立、可替换并保留裁切信息。
- `decoration` 图片必须与 `content` 图片分组隔离。
- 横图、竖图和方图都要验证裁切；换图后不能沿用不适合新图的裁切。
- 模板封面另存为 `template_24.jpg`，不计入 9 项装饰素材。

### 6.3 标题和分页

- 保留 `sourceTitle`，不得用省略号或截断原题代替原始标题。
- 标题变短只是展示适配，不能改变正文语义。
- 正文超量时按原项目顺序分页。
- 标题处理和正文分页分开，不能因为长标题把四项正文强行拆成四个单项页。
- 继续使用项目已有的错误区分：`ITEM_TITLE_TOO_LONG`、`TEMPLATE_TEXT_OVERFLOW`、`TEMPLATE_PAGINATION_EXPLOSION`。

## 7. 开发阶段和自动确认

G0～G8 连续执行，不设置逐阶段、逐页面、逐素材或逐测试的人工确认。执行者完成当前任务、运行必要验证并保存证据后自动继续。

| 自动检查点 | 覆盖阶段 | 自动确认内容 | 通过后动作 |
|---|---|---|---|
| C0 预检检查点 | G0～G1 | 源文件、模板 ID、工作树、页面映射、权利策略和素材范围明确 | 自动进入 G2 |
| C1 技术链检查点 | G2～G6 | 三页探针、9 项素材、5 张样稿、12 页 MVP、语义和专项测试通过 | 自动进入 G7 |
| C2 候选冻结检查点 | G7～G8 | 18 页生产版、注册、编辑换图、受影响视口、PPTX 往返和 QA 证据通过 | 自动记录 `G8_PASS / G9_PENDING`，等待人工确认 |

阶段任务仍按以下顺序执行：G0 预检、G1 页面盘点与素材、G2 技术探针、G3 规格与 MVP、G4 代表样稿、G5 语义专项测试、G6 生产版与注册、G7 真实功能 QA、G8 最终核验。阶段编号描述工作顺序，不再作为人工审批门禁。

普通测试失败、文字溢出、素材不合格、裁切错误和局部兼容问题，在范围内自动诊断、修复和重验。只有缺少新的外部授权、需要不可逆操作、需要生产操作或发生重大范围扩展时才暂停。

G4 固定为 5 张样稿：`cover-city`、`contents-4`、`transition-city-left`、`content-text-4`、`end-city`。`content-image-1` 在 G2 单独验证，`content-metrics-4` 在 G7 验证，不重复计入 G4。

## 8. 验收清单

### 8.1 必须验证

- 模板 JSON、封面和所有实际引用资源存在且路径正确。
- 生产版包含 2 个封面、6 个目录、2 个章节、6 个内容页、2 个结束页。
- 标题、正文、目录项目、指标和行动信息完整保留。
- 内容图片可替换，固定装饰不被替换。
- 横图、竖图和方图裁切合理。
- 长标题不会被静默截断。
- 内容超量时按项目原顺序分页。
- 生成结果可以保存、重载、导出 PPTX 并重新导入。
- 相关错误有明确反馈，不把失败结果当作成功。

### 8.2 按实际影响执行

- 修改模板 JSON 或构建器：运行模板专项和受影响的渲染测试。
- 修改图片槽、裁切或装饰角色：重验换图和 PPTX 往返。
- 修改公共渲染器或导出器：扩大旧模板回归范围。
- 修改模板选择页或编辑器外壳：检查 1920×1080、1366×768、768×1024、390×844 四种视口。
- 不修改前端入口时，不把全站按钮交互和响应式整改增加到本模板范围。
