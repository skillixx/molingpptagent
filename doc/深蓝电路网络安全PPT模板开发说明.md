## 3. 视觉与素材规格

### 3.1 统一风格

- 背景采用深海军蓝到灰蓝的低对比渐变，强调色参考 `#A0C9D8`、`#81B8CB`。
- 电路线条细、节点少、发光克制；标题和正文区域优先保持干净。
- 中文优先使用项目可用的微软雅黑，英文及数字优先 Arial，开发时核实编辑和导出环境。
- 标题、条目标题、正文及说明有明确层级。字号、边距和文字容量通过实际渲染确定，正文超量时分页，不无限缩小字体。

### 3.3 素材制作要求

**模板所需图片可以使用 GPT2 图片模板生成。** 适用范围包括 A1～A8 固定背景与装饰，以及确有需要的业务展示样例图。展示样例图仍作为业务图片管理，不增加固定素材数量，也不替代用户的实际业务图片。后续明确启动开发后，可在上述范围内使用该生成方式；当前只记录规划，不调用图片工具。

1. 背景、角饰、锁形和网络球分层制作；8 项素材可以由统一基础画面派生，不要求 8 次独立生成。
2. 素材不带文字、数字、公司名或水印；透明 PNG 使用真实透明通道，边缘无白边、杂色和裁断。
3. 素材来源明确，记录文件版本、尺寸、用途、检查结果和引用页。复用原稿照片或字体前核实使用来源，或采用替代素材。
4. 将素材放入实际页面检查清晰度和文字可读性，达到要求后停止迭代；不设主观相似度或逐像素复刻门槛。
5. 正式素材与测试图片、中间稿分开管理。正式模板只引用项目可访问资源，不引用桌面或临时路径。

GPT2 图片模板是可采用的图片生成方式，不代表工具一定暴露同名底层模型。实际模型名称按返回信息记录，未暴露时写“工具未暴露”；不为证明模型名称重复生成合格素材。素材按当前页面需要分批制作，可与版式开发交错推进，不预设固定调用次数。

## 4. 内容填充与编辑规则

### 4.1 页面、文字和图片如何标记

| 对象 | 实现要求 |
|---|---|
| 页面 | 使用第 2 节的页面类型；三个专项页设置对应 `layoutKind` |
| 标题和正文 | 使用项目现有 `textType` 和条目关联规则，保留独立文字对象 |
| 编号、标签、分隔线 | 使用可编辑文字和形状，清理空条目时同步清理对应编号 |
| 业务图片 | 标记 `imageType=content`，与所属条目保持对应，允许替换及裁切 |
| 固定背景和装饰 | 标记 `imageType=decoration`，与可能被清理的业务组分开，不参与业务换图 |
| 流程和关系图 | 节点、编号、标签、说明及连线分别构建，保留业务顺序和关系 |
| 指标 | 名称、数值、单位、说明分别可编辑，数据来自输入；首版不实现图形比例联动 |

A8 网络球只作固定插图；六节点关系图使用可编辑的中心主题、节点和连线。生成图片内部的像素和线条不属于可编辑对象要求。

指标版式已声明 `metricValueField=value`、`metricUnitField=unit`，数值和单位分别填入 `itemNumber`、`itemUnit`；空单位只清理单位框，回退正文时数值与单位同时保留。

源文件母版占位符不能直接替代上述标记。复用现有接口和路由，只为实际缺失或失败的行为修改公共实现，代码入口见附录 B。

### 4.2 选版和分页

1. 按页面类型、条目数、图片数、实际文字容量和指定布局选版；相同固定输入保持稳定结果。
2. 目录 2～6 项精确选版；1 项复用两项版式并清理空槽；超过 6 项保序续页，例如 7 项为 6＋1。
3. 普通正文每页最多 4 项；更多项目和超长正文按实际容量分页。不能仅因条目标题长，将四项页拆成四个单项页。
4. 原始标题、正文、数字、单位和项目顺序不得丢失。展示标题适配时保留 `sourceTitle`，并在可见内容中完整保留原题，不能静默截断或以省略号替代。
5. 业务图片与条目一一对应。数量不匹配时明确反馈，不复制图片凑数或忽略图片。带图条目分页后仍须能对应原图片。
6. 专项页按四步骤、四指标、六节点设计。数量或文字容量不适合时，使用续页或普通正文完整承接，保留标签、数值、说明及业务关系。
7. 同时含图片和指标等混合内容时，用已有合适版式分别承接，不为匹配某版式删除内容。缺少必需字段、空内容或非法数据沿用项目校验，不补造业务数据。

### 4.3 编辑与设备适配

支持修改文字、替换图片、裁切、保存重开和 PPTX 导出往返。横图、竖图、方图替换后不能拉伸，固定装饰保持不变。

幻灯片画布始终为 16:9。桌面、笔记本、平板和手机通过编辑器布局、缩放及工具栏适配操作，不将幻灯片自动重排为手机长页。本次新增或修改的按钮提供加载、成功、失败或重试等明确反馈。

**推进方式：**先核对编号和当前工作区，随后持续制作素材、实现基础及完整版式，并随可运行样例穿插内容填充、本地注册、编辑导出和设备检查。基础版通过、素材全部齐备或 T7 全部结束，都不作为开始其他独立工作的前置审批。

T1～T7 检查通过后自动确认对应工作并继续；普通缺陷自动修复、重验，同时继续独立工作。T8 的检测也自动执行，但闭合必须经过人工确认。失败或未执行的检查如实记录，Git 交付和生产操作不属于 T1～T8。

**T8 闭合流程：**完成当前候选的自动检测 → 提供可检查的程序或样例、导出文件及检测结果 → 将 T8 记为“待人工确认”，保持 Goal 未完成 → 用户明确确认当前候选完成 → 记录确认、将 T8 改为“已完成”并完成 Goal。不得根据沉默、超时或自动检测通过推定人工确认。

人工检查提出问题时，继续修复并重验受影响部分，更新候选后再次提交确认。闭合沿用 T8，不新增 T9；确认仅覆盖模板验收和闭合，不自动授权 Git 交付或生产操作。
