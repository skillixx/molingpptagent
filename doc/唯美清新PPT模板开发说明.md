## 2. 视觉规范

- 保留蓝紫朦胧背景、白色文字、少量粉金光斑、半透明圆环和轻量边框的整体风格，用于项目介绍、工作汇报、案例展示和阶段总结。
- 深蓝用于正文底色，淡紫与青蓝提供层次，暖色光斑主要放在边缘。封面可以更明亮，正文背景必须更暗、更均匀。
- 主阅读区避免高亮光斑和复杂纹理；白字不能落在亮粉色背景上。卡片、边框和装饰不挤占正文空间。
- 中文优先使用微软雅黑，英文和数字优先使用 Arial。开发时确认编辑器和导出环境实际可用的字体，并在代表页确定标题、正文、标签的字号层级和可读下限。
- 标题、正文、数字、日期、流程节点和连接线使用原生可编辑元素；业务图片使用可替换图片槽。装饰图只提供视觉氛围。
- 幻灯片保持 16:9，通过缩放适配屏幕，不随手机宽度重排导出内容。检查受影响的模板选择、预览和编辑入口在桌面、笔记本、平板、手机上的显示；本次修改的交互入口必须有操作反馈。
- 不设置逐像素复刻或与其他模板风格差异的验收门槛；以文字可读、内容完整和功能稳定为准。

- 结束页补充文字优先复用现有填充能力；若当前协议不支持，至少保持在线编辑及导出可编辑，不为此扩展通用协议。

### 4.2 素材使用规则

1. 按原稿配色和构图制作新的无文字素材，不以整页截图替代可编辑页面。素材中不包含标题、正文、日期、数字、Logo、水印或业务图表。
2. A5、A6 保留真实透明通道，不能有假透明棋盘格、明显白边或黑边。A6 按版面需要使用，不要求每页叠加；装饰不能遮挡文字和图片主体。
3. A5 是装饰圆环，不表示百分比，不承担业务图片裁切边界。首版指标使用独立数字和单位，不制作数值联动环形图。
4. 记录素材来源、用途、制作方式和版本。工具未暴露模型名称时如实记录“工具未暴露”，不因此阻塞交付；清晰度、透明度和可读性合格后停止迭代。
5. 试生成、测试图片与正式素材分开保存，正式模板只引用检查通过的版本。原生信息卡片、线条、节点和文字不计入装饰素材数量。
6. 业务照片使用可替换槽位；小图标优先复用已有矢量资源，必要时以编号表达。模板选择封面从正式封面版式导出，不计作第 7 张装饰素材。

### 5.2 复用现有接口

- 模板 JSON 由构建脚本生成，使用第 3 节的页面类型；在现有模板注册列表登记编号、名称和封面。具体文件见第 6.2 节。
- 正文按现有 `textType` 协议标注页面标题、项目标题、正文和编号。普通内容对应 `title`、`itemTitle`、`item`、`itemNumber` 等现有槽位，P0 时核对与各页面类型的实际字段映射。
- 封面使用 `data.title` 承载主标题；副标题与汇报人、日期等补充信息合并在可编辑的多行 `data.text` 中，不新增业务字段，也不自动补造用户未提供的信息。
- 流程、时间轴、指标分别使用现有 `layoutKind: process / timeline / metrics` 机制，容量限制对应 4、5、4 项；普通正文与图文容量按其库存标注。已有类型识别不代表本模板已经兼容，需要固定样例验证。
- 指标复用 `metricValueField: value` 与 `metricUnitField: unit`；数值、单位、名称、解释保持独立槽位，不能把模板示例数字或百分号固定在图片里。时间轴日期和阶段来自输入，不补造时间信息。
- 优先复用当前选版、填充、分页和导出机制；仅在本模板存在具体缺口时修改公共实现。协议背景可参考 [PPT 结构说明](PPT_Structure.md)，其中历史页数、10 项目录和旧图片标记不覆盖本文约定。

### 5.3 内容与图片必须满足的规则

- **内容完整：**保留原始标题、正文和项目顺序。长标题先换行和调整版式；确需改变展示标题时保留 `sourceTitle`，并让原始标题在正文或对应阅读位置完整出现，不能截字冒充语义适配。
- **合理分页：**标题适配与正文分页分开。四项页不能仅因项目标题长就变成四个单项页；正文真正超出容量时有序分页，不持续缩小字号，不丢失或重复内容。
- **角色分离：**图片元素中，装饰标记为 `imageType: decoration`，业务图片标记为 `imageType: content`；原生背景字段保持固定背景角色。换图只更新业务槽位。
- **关联与裁切：**1～4 张业务图片逐项绑定对应文字，保持顺序；不同比例通过裁切适配，不拉伸变形，并保留导出和重新导入所需的尺寸、裁切信息。
- **异常反馈：**缺图、图片读取失败、数量不匹配或特殊版式容量不足时，有明确错误或约定回退。不得出现静默错配、虚假内容或无法解释的空白页。

3. **确认后闭合：**收到用户针对当前候选的明确确认，例如“确认通过，完成闭合”，记录确认内容与候选版本，更新交付记录和最终报告，然后将总 Goal 标记为完成。这里的闭合不包含提交、推送、PR、合并或生产操作；这些动作仍需各自明确授权。
