### 自动确认规则

1. 根据实际依赖安排任务，素材、版式、填充和功能检查可以交错推进。样例检查融入开发，不设置独立样例审批。
2. 不要求 T3～T5 全部结束才开始本地注册验证；可加载候选具备后就检查入口，随后随开发更新。最终交付仍须包含完整的 24 个版式和五张背景。
3. 每次检查有结果后，由执行者自动记录“通过”或具体问题，并继续可开展的任务；开发过程无需逐页面、逐素材或逐测试请求确认，T8 最终人工确认按第 5 节执行。
4. 普通范围内问题自行诊断、修复、重验，不因单项失败停止全部工作。相同输入、代码和环境下已有有效证据不重复检查。
5. 自动检测全部完成后核对第 5 节，准备可检查的候选与证据，记录“T8 自动检测通过，待人工确认”。收到用户明确确认后才完成 T8 闭合和 Goal，不能自动代替用户确认。

自动检查必须依据真实结果，失败或未检查的项目不能自动勾选为通过。除 T8 约定的最终人工确认外，只有确实缺少用户才能提供的信息、需要新的范围或操作授权，或外部条件阻止相关任务继续且无法绕开时，才说明具体原因并请求介入；其他独立工作继续推进。

## 3. GPT2 图片模板使用说明

模板中需要的图片可以用 **GPT2 图片模板**生成。它是本任务允许采用的图片制作方式，不改变五张核心背景和业务图片槽的定义。

| 图片 | 生成方向 | 使用边界 |
|---|---|---|
| A1 城市封面 | 黄昏城市、蓝天、暖金灯光，上方留标题区 | 固定背景，`decoration` |
| A2 星云目录 | 深蓝黑、边缘暗红或紫色星云，文字区低干扰 | 固定背景，`decoration` |
| A3 建筑章节 | 两侧仰视玻璃建筑，中央留章节框区域 | 固定背景，`decoration` |
| A4 会议章节 | 窗边会议、左右匿名剪影，中央留文字区 | 固定背景，`decoration` |
| A5 城市结束 | 延续 A1 色调，减少细节、扩大文字留白 | 可由 A1 制作变体，`decoration` |
| 必要的通用示意图或测试图 | 按图片槽验证需要准备，标明示意或测试用途 | 与正式背景分开管理；业务槽仍为可替换的 `content` |

具体文件名和构图以开发说明第 3 节为准。不要生成带完整标题、正文、指标或流程的整页图片来替代可编辑模板。背景不得包含文字、数字、Logo、网址或水印。

执行时使用实际可用的图片生成工具。沿用“GPT2 图片模板”称呼，但实际模型名称仅依据工具返回记录；未暴露时写“工具未暴露”。记录提示词、工具、成品路径和检查结果，不用文字描述冒充已生成素材。

成品检查尺寸、格式、清晰度、构图以及叠加文字后的可读性，通过后停止迭代。图片最终复制或保存到项目模板资源目录，再通过 `/api/data/` 引用，不能只保存在工具临时输出目录。

如生成能力不可用，先继续不依赖新素材的工作，并明确报告受影响任务。使用已有合格、授权明确的素材前核对是否满足同一设计要求；不擅自启用新的付费 API、计费或规划外素材。

## 4. 验证与实施约束

- 标题、正文、编号、数字和联系信息保持可编辑；菱形框、流程箭头、时间线和分隔线使用原生形状。
- 保留 `sourceTitle`、原正文和原项目顺序，标题适配与正文分页分开，不能因长标题异常拆成多个单项页。
- 普通正文每页最多 4 项，目录每页最多 6 项；专用布局按约定容量选择或保序降级。
- 业务图片与条目一一对应，固定装饰和业务图分组隔离。横、竖、方图替换后裁切可用。
- 固定语义数据、Fakes/Mocks 和隔离依赖优先用于验证模板逻辑。渲染缺陷先增加可复现的失败测试，再修复。
- 真实模型或 Worker 验证按实际影响确定，不将本次图片生成方式扩大为对生产任务或新增计费的授权。
- 如需运行本地候选，先确认相关服务的端口、PID、命令行、工作目录和项目归属，只操作实际必要的项目服务；健康的旧版本服务不能代替当前候选验证。
- 只检查受影响入口的桌面、笔记本、平板和手机适配；公共渲染或导入导出逻辑变化时才扩大相关旧模板回归。
- 编写代码使用中文注释说明非显然逻辑，保留用户已有修改，不清理无关产物。

### 5.2 人工确认与闭合

- **准备确认材料：**先提供当前候选的可检查入口或交付文件、模板编号、检测摘要、必要截图或 PPTX 往返证据、已知限制及候选标识。已经运行本地候选时提供已验证地址，让用户能够检查具体结果。
- **等待明确答复：**自动检测全部通过后请求用户确认。用户明确表示当前候选“确认完成”或“可以闭合”等同等意思，才满足人工确认条件。未回复、等待超时或机器检测通过不算人工确认。
- **确认后闭合：**记录确认内容和对应候选，更新 T8 为“已确认，已闭合”，然后将实际 Goal 标记为完成并输出最终交付说明。闭合是 T8 的最后一步，不新增开发阶段。
- **反馈后重验：**用户指出问题时，继续范围内修复，重验受影响部分，再提供更新后的候选并等待确认；不能用旧候选的确认覆盖新的改动。

完整完成条件为：第 5.1 节全部通过，加上第 5.2 节用户明确确认。等待人工确认期间 T8 和 Goal 保持未完成，不能自动闭合。人工确认闭合不自动授权 Git 交付或生产操作。
