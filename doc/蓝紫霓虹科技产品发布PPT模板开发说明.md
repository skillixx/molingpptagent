## 1. 目标与规范

### 1.1 开发目标

将用户提供的 `C:/Users/sk20/Desktop/产品发布 (6).pptx` 改造成项目可选择、可自动填充内容的静态 PPT 模板。用户应能修改文字、替换业务图片、保存重开，并导出可继续编辑的 PPTX。

| 项目 | 约定 |
| --- | --- |
| 模板名称 | 蓝紫霓虹科技产品发布 |
| 首版范围 | 原稿 25 页对应的 22 个基础版式全部保留，详见第 2 节 |
| 适配变体 | 已实现 17 个：长标题封面 1 个、目录容量 4 个、普通正文容量 6 个、单图正文容量 6 个，共 39 个候选版式 |
| 画布 | 16:9，模板坐标采用项目常用的 1000 × 562.5 |
| 模板编号 | `template_30`，显示名称为“蓝紫霓虹·科技产品发布” |
| 首版不包含 | 原稿动画、背景音乐及新增视频、多图画廊、数据驱动图表能力 |

原稿的全部页面已完成渲染检查，项目解析器可以读取 25 页。以下三项会直接影响实现：

- 封面“5G 数据时代”是图片字，需要改成可编辑主标题。
- 手机框包含 EMF，需要转换成网页可显示、导出可用的素材。
- 原稿使用的部分字体不能直接在网页中复用，需要验证字体替换后的排版。

原稿读取成功不代表新模板的编辑、换图和导出验收已经通过。附件文案只作样例，正式内容由用户输入。

### 1.2 视觉规范

| 项目 | 实现要求 |
| --- | --- |
| 色彩 | 深蓝黑底色，青蓝与蓝紫为主，少量紫红强调 |
| 背景 | 正文区使用低对比纹理，光束、粒子和主要装饰集中在侧边或下方 |
| 字体 | 优先使用项目已有字体，以微软雅黑、Arial 作为适配起点 |
| 字号与留白 | 按真实内容容量确定，标题和正文有独立空间，不能无限缩字解决溢出 |
| 装饰风格 | 科技光环、城市平台、数据雕塑、星球轨道与设备框保持统一色调 |
| 通用性 | 优先采用无固定“5G”字样的装饰，不要求额外维护一整套 5G 专用素材 |
| 参考保留 | 保留视觉方向和页面用途，允许为可读性调整间距、字体及装饰位置 |

### 1.3 核心实现要求

1. **文字与业务信息可编辑。** 标题、正文、编号、指标数值、单位和关系说明不能合成进背景图片；表达数据的图形保留必要的独立对象。
2. **内容与顺序完整。** 不静默截断标题或正文，不漏条目。展示标题适配沿用项目标题保真协议，保留原始标题。
3. **容量有明确边界。** 长标题与正文分页分别处理，不能只因标题过长就把多项页拆成多张单项页。分页或改用通用版式时保留原数据及图文对应关系。
4. **图片角色分离。** 业务图片使用 `imageType: content`，固定装饰使用 `imageType: decoration`。设备框与屏幕图片独立，换图只更新内容槽；保持图片比例，尊重显式裁剪，避免重复裁切。
5. **版式可以被选中。** 每个基础版式和变体都有明确的合法输入、匹配条件及超量处理规则，不能只制作静态样例。
6. **受影响的界面可操作。** 幻灯片保持 16:9 缩放，模板入口、编辑器、弹窗和工具栏适配桌面、笔记本、平板、手机。新增或修改的按钮有明确反馈，真实功能失败不能伪装成成功。

### 2.2 开发时需要补齐的版式定义

在 T1 确定字段，并在 T3—T5 根据实际布局补齐容量和选版规则。每个版式至少记录：

| 定义项 | 需要写清的内容 |
| --- | --- |
| 页面与文字槽 | 实际页面 ID、`cover/contents/transition/content/end` 类型及各文字槽的 `textType` |
| 容量 | 允许的项目数量、业务图片数量、可容纳的文字范围及长内容处理方式 |
| 选版条件 | 对应语义输入、专项类型或变体条件；相同类型和容量的版式也要有明确区分 |
| 超限与异常 | 保序分页、切换通用版式或明确报错的条件；不得丢弃原文、数值或关联图片 |
| 固定样例 | 能命中该版式的一组输入，以及验证容量边界所需的样例 |

优先复用现有选版机制。专项映射是否需要修改公共逻辑，由实际缺口决定；不直接把规划名称新增为代码枚举。新增的目录、长标题和正文容量变体记录在对应 L 标识下，不用变体替代尚未完成的基础版式。

当前实现的调用方式：普通内容传入 `data.items` 及可选 `images` 即可，城市、圆形主题、雕塑、设备框等源版式参与默认选版；需要指定源版式时使用 `data.variant: L04` 等别名。专项页按 [版式目录](assets/template_30_qa/layout-catalogue.json) 提供 `layoutKind` 和可选变体。通用回退页可用其页面 ID 作为变体别名精确选择。

交错流程、环形与扇形关系中的文字和编号使用从零开始的 `slotIndex` 显式绑定项目顺序；不声明该字段的历史模板仍按原有坐标顺序处理。

## 3. 素材清单

### 3.1 复用与按需生成

A01—A12 表示 12 种使用角色，不要求 12 个独立文件，也不要求生成 12 张新图。开发者在 T2 为实际使用项记录“来源、处理方式、最终文件、引用版式”，按页面需要分批准备。

| 标识 | 素材与构图 | 用于 | 默认处理 | 何时补做或生成 |
| --- | --- | --- | --- | --- |
| A01 | 封面／结束背景：蓝青光环、少量紫红光束，中央留标题空间 | L01、L22 | 共享原稿无字背景 | 实际裁切后不清晰或标题区无法使用 |
| A02 | 正文背景：深蓝星空、弱粒子旋涡，文字区低对比 | L04—L21 | 优先复用，按版式调整裁切 | 原图清晰度不足或强纹理影响阅读时优先重制 |
| A03 | 目录背景：保留完整目录区，机器人位于侧边 | L02 | 复用原稿整体背景 | 整体构图无法容纳目录时，改为背景与 A05 组合 |
| A04 | 章节背景：中上部放标题，下方放城市或平台 | L03 | 优先复用原稿，或组合 A02 与 A06 | 组合后仍无法满足标题留白时再补独立背景 |
| A05 | 机器人侧脸：金属质感、蓝紫反光、朝向文字区 | L02 | A03 已包含机器人时不另做 | 需要独立移动且原稿无法直接分离时准备透明 PNG |
| A06 | 智慧城市与悬浮平台：等距城市、玻璃平台、蓝紫灯光 | L03、L04 | 复用适用部分，主体放侧边或下方 | 原图固定“5G”字样影响通用性，或无法满足构图时生成无字版本 |
| A07 | 数据雕塑：抽象数据环、立体流线或带状结构 | L10 | 优先采用通用无字造型 | 原稿 5G 雕塑无法用于通用主题时补做 |
| A08 | 星球／轨道：细轨道、弱发光，不挤占正文 | 内容页标题区 | 复用素材，简单轨道用原生形状 | 只有现有素材与形状不能满足实际效果时补图 |
| A09 | 显示器框：规则屏幕，机身与照片分离 | L05 | 复用原框，建立独立屏幕图片槽 | 原框边缘、清晰度或屏幕范围不合格时处理 |
| A10 | 笔记本框：规则屏幕，底座不遮挡文字 | L16 | 复用原框，检查透明边缘与层级 | 原框无法稳定换图或显示时处理 |
| A11 | 手机框：正面机身，无固定照片 | L18 | 将 EMF 转为网页和导出可用格式 | 格式转换后仍不合格时再重制 |
| A12 | 透视网格与定位点：位于页面下方，上方留文字 | L17 | 纯装饰可合并；业务节点保持独立 | 原稿组合不适合当前布局时才补做 |

### 3.2 素材规格

| 类型 | 建议规格 | 检查重点 |
| --- | --- | --- |
| 背景 | 16:9，优先 2560 × 1440，以 1920 × 1080 为建议最低目标 | 看实际裁切和显示清晰度，不通过机械放大凑像素；不嵌入标题或正文 |
| 透明主装饰 | PNG 真透明，长边建议 1600—2400 px，按使用尺寸调整 | 无白边、伪透明棋盘格、意外文字，主体不挡内容 |
| 设备框 | 尺寸覆盖实际展示需求，屏幕比例与槽位一致 | 机身不被业务图片覆盖，换图不拉伸、不重复裁切 |
| 小装饰与图标 | 优先复用或采用项目已有形状 | 实际显示清楚，保持统一色调 |

需要生成图片时，提示词写清用途、主体位置、留白区、色彩、宽高比和透明要求。素材达到使用要求即停止迭代，不为补足数量重复生成。

主标题、正文、数字、SWOT 标签、步骤名称、关系说明及简单箭头连线由模板元素实现。业务照片是可替换内容，不计入固定装饰库存；测试图片与正式发布资源分开管理。

### 3.3 gpt2 图片生成说明

**模板中需要的图片可以使用用户指定的 gpt2 图片生成方式制作。** 适用范围包括当前版式需要补充的背景、固定装饰、设备框，以及明确需要的示例配图。业务图片仍须放入可替换内容槽，文字与业务数据保持原生可编辑。

这项说明作为未来正式执行开发时的素材方案，不要求全部素材重做。沿用 A01—A12 的复用和生成条件，合格源素材可以直接复用；需要补做时按当前页面分批生成，并按第 3.2 节检查质量。

`gpt2` 沿用用户指定称呼，本文不预设 API 模型 ID。执行时核对所用图片工具的实际选项，记录实际工具和可见模型信息；未暴露时记录“工具未暴露”，不虚构模型名称，也不为证明名称重复生成合格图片。

本 Goal 已正式执行，共交付 8 个位图素材：4 个原稿复用／格式转换，4 个通过 image_gen 生成或编辑。生成和编辑提示词、实际尺寸及来源见 [素材检查记录](assets/template_30_qa/asset-inspection.json) 与 [提示词记录](assets/template_30_qa/image-generation-prompts.json)，实际模型均按“工具未暴露”记录。该许可不扩展为真实业务模型任务或生产操作授权。

### 4.1 任务、输入与产物

以下为任务分工；当前进度和结果见配套 Goal 规划。开发使用第 5 节统一验收，不再另建一份重复的完成条件。

| 任务 | 输入 | 工作与产物 | 该任务完成的判断 |

| T1 页面与字段定义 | 本文、原稿、现有模板协议 | 核对 L01—L22，登记页面类型、字段、选版方式和待验证容量；核定可用模板编号 | 25 页有对应，字段及编号明确，特殊版式的实现缺口已定位 |

T3 负责 L01—L04、L06、L07、L09、L10、L22，共 9 个通用版式；T4 负责其余 13 个专项版式。实现细节可以共享，不要求为每个版式编写一套重复逻辑。

### 4.2 执行方式

**T1—T7 自动判断、自动检查并连续推进，不等待用户逐项回复。T8/G8 的检查仍自动执行，仅在最终闭合前保留一次人工确认。**

- 先核对当前修改需要的编号、协议和工作区，再按页面滚动推进素材、实现及容量适配。其余字段和文档边开发边完善，不要求所有页面定义或素材先齐全。
- 模板编号、布局微调、合格素材复用、按需 gpt2 图片生成、必要格式转换和范围内修复由代理自行处理，不另设人工预览或批准步骤。
- 必要的本地预览、固定数据验证及 Mock Worker 检查自动执行。检查通过后自动记录结果并继续；失败时自动诊断、修复和重验，只影响实际依赖该问题的工作。
- 只检查当前实际影响，复用未变化条件下已通过的证据。非阻塞的风格意见、可选增强和后续功能记录为备注，不反复审查或阻断推进。
- 全部约定能力完成且 G8 自动检测通过后，准备可检查的候选、样例和结果，记录为“待人工确认”。收到用户对当前候选的明确通过答复后，才能标记 G8 和总 Goal 完成；确认前不执行闭合操作。
- 除 G8 最终确认外，仅对无法自行取得的必要输入、无法绕开的真实阻塞或范围外授权事项提问，其他工作继续。人工检查提出问题时自动修复并重验，再提交修复后的候选确认。

自动确认依据真实结果，不会把未检查或失败的项目改成通过。提交、推送、PR、合并和生产操作仍遵循项目的独立授权规则。
