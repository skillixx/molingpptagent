本文定义模板的开发范围、设计规范、页面系统、素材规格、实施任务和验收标准。本文不代表模板已经开发，也不授权自动开始图片生成、代码修改、服务启动、测试、提交、推送或部署。

## 2. 开发者先看

实施者应先理解以下六条约束：

1. 参考 PPT 只提供版式和视觉方向，原图片、字体、音频和示例文字不进入生产模板。
2. 先完成 12 页 MVP，并验证真实生成、图片保护和 PPTX 导出；通过后再扩展到 18 页。
3. 背景和固定装饰必须标记为 `imageType: "decoration"`，只有内容图片可以标记为 `imageType: "content"`。
4. 目录必须精确支持 2、3、4、5、6、10 项；正文至少覆盖 1～4 项，超量和长正文必须无损分页。
5. 第 18 页原生图表不进入首版模板，避免触发当前 PPTX 导入器解析失败。
6. 自动验收最多进入 `READY_FOR_CONFIRMATION`，只有用户明确确认后才能闭合为 `DONE`。

推荐开发顺序：

`预检 → 权利审计 → 原创素材 → 12页MVP → 语义标注 → 注册与测试 → 端到端QA → 18页扩展 → 最终验收`

## 3. 模板目标与范围

### 3.1 目标

“深空星环科技”面向科技、AI、数字化、航天科普和产品方案类演示。开发完成后应支持：

- 封面、目录、章节、内容和结束五种页面类型。
- 目录 2、3、4、5、6、10 项精确选版。
- 无图、单图和双图内容。
- 超量内容和长正文无损分页。
- 内容图片由 AI 填充或用户替换。
- 背景、星环、星座连线和光晕保持固定。
- 无图片输入时不出现破图和异常空框。
- 生成结果可编辑、可导出 PPTX、可重新导入。
- 桌面、笔记本、平板和手机无横向溢出。
- 模板选择、生成、保存、换图、导出和失败重试按钮均有明确反馈。

### 3.2 不做

- 不复用授权不明确的参考媒体、字体、音频和示例内容。
- 不重写 PPTist 编辑器，不新增 PowerPoint 原生图表解析器。
- 不内置真实人物、企业 Logo、产品界面、证书、业务数据和固定内容照片。
- 不为了单个模板破坏现有模板的选版、分页、图片或导出行为。
- 不在规划阶段生成正式素材、模板 JSON、封面或测试证据。

## 5. 视觉规范

### 5.1 设计定位

- 主题：深空、轨道、星环、星尘和轻量科技信息图。
- 语气：克制、理性、有空间纵深，不做高饱和游戏界面或密集仪表盘。
- 主视觉：每页只保留一个焦点，标题、数据和内容图片不能互相争夺层级。
- 背景允许跨页复用；内容图片默认不跨页复用。

### 5.2 颜色

| 用途 | 色值 | 说明 |
|---|---|---|
| 主背景 | `#04131F` | 全局深空底色 |
| 辅助深蓝 | `#0A2942` | 内容分区和局部层次 |
| 主强调青 | `#19C7D9` | 星环、节点和关键信息 |
| 辅助蓝 | `#4E7FFF` | 图片边框和图形层次 |
| 少量蓝紫 | `#8B5CFF` | 章节和重点节点 |
| 少量暖橙 | `#F3A846` | 只用于可编辑的关键编号或对比 |
| 主文字 | `#F7FBFF` | 标题和正文 |
| 次文字 | `#B7C6D4` | 说明和次级信息 |

暖橙和蓝紫不能成为大面积背景。红色只用于真实警告或负向语义。

### 5.3 字体和字号

| 层级 | 字体 | 最小字号 |
|---|---|---:|
| 封面标题 | 微软雅黑 Bold | 50px |
| 章节标题 | 微软雅黑 Bold | 44px |
| 页面标题 | 微软雅黑 Bold | 35px |
| 内容项标题 | 微软雅黑 Bold | 24px |
| 正文 | 微软雅黑 | 16px |
| 英文和数字 | Arial | 跟随对应层级 |
| 非核心说明 | 微软雅黑 | 14px |

自动缩字不得低于 12px。仍无法容纳时必须改选低密度版式或分页，不能截断正文。

### 5.4 画布和安全区

- 逻辑画布固定为 `1000 × 562.5`。
- 可编辑信息默认限制在 `x=64..936`、`y=42..516`。
- 内容页左右边距保持一致。
- 单行页面标题不得因替换文案自动变成两行。
- 章节装饰不得穿过标题。
- 背景中央至少 70% 为低细节区。
- 边缘星座装饰中央至少 85% 透明。
- 底部装饰不得高于页面高度的 25%。
- 内容图片槽必须验证横图、竖图和方图裁剪。

### 5.5 位图与可编辑形状

允许使用原创位图：

- 深空星点背景。
- 星云和局部光晕。
- 复杂轨道星环。
- 边缘星座连线。

必须使用 PPTist 可编辑形状：

- 章节数字圆、普通圆环和短轨道线。
- 节点、连接线和普通粒子。
- 三角形、六边形、矩形和半透明卡片。
- 目录编号、时间轴、进度条和百分比条。
- 简单柱状图、流程节点和对比结构。
- 图片边框、蒙版、角标和常规阴影。

## 6. 页面系统与选版规则

### 6.1 页面矩阵

| 页面类型 | MVP 数量 | 生产数量 | 稳定 ID / 用途 |
|---|---:|---:|---|
| 封面 `cover` | 1 | 2 | `cover-orbit`、`cover-image` |
| 目录 `contents` | 6 | 6 | `contents-2`、`contents-3`、`contents-4`、`contents-5`、`contents-6`、`contents-10` |
| 章节 `transition` | 1 | 2 | `transition-orbit`、`transition-nebula` |
| 内容 `content` | 3 | 6 | `content-text-2/3/4`、`content-focus-1`、`content-image-1/2` |
| 结束 `end` | 1 | 2 | `end-orbit`、`end-action` |
| 合计 | 12 | 18 | MVP 通过后才能扩展生产版 |

MVP 先验证纯文字主链路。带图封面、第二章节、单结论、单图文、双图文和行动结束页在 G7 扩展。

### 6.2 选版规则

1. 无内容图封面使用 `cover-orbit`；一张合法内容图且标题满足安全区时使用 `cover-image`。
2. 目录 2、3、4、5、6、10 项精确匹配对应版式，其他数量按渲染器能力无损分页。
3. 章节显式变体优先；没有变体时按章节序号稳定轮换两个版式。
4. 无图 1 项使用 `content-focus-1`；2～4 项使用对应纯文字版式。
5. 单图和双图分别使用 `content-image-1`、`content-image-2`。
6. 超量和长正文按可读容量分页，保持字符、顺序和语义关联。
7. 带图长正文分页时，内容图只保留在首段；固定装饰每页保持稳定。
8. 图片数量、图片尺寸或显式版式不合法时返回明确的 `TemplateRenderError`，不得静默选错版式。

### 7.3 图片生成约束

- 模板所需的原创背景和透明装饰可以优先使用 GPT Image 2（`gpt-image-2`）生成；它只用于素材生产，不用于伪造真实产品、界面、人物或证据。
- 实施时应通过适用的图片生成技能或工具调用 GPT Image 2；如果工具未提供该模型或未暴露实际模型名称，应如实记录并使用其他授权明确的素材方案，不得伪造模型信息。
- 每种素材使用独立提示词单独生成，不生成素材拼图。
- 无文字、数字、Logo、水印、伪代码和固定年份。
- 无真实人物、企业、学校、机构和可识别品牌。
- 无手机、芯片、手表、电脑和其他可识别产品。
- 无真实产品界面、假截图、证书、业务报表和科学证据。
- 只生成抽象深空、轨道、星环、星座和星云光效。
- PNG 必须具有真实 Alpha 通道，不能用白底或棋盘格伪装透明。
- 不使用 Python 或程序化绘图生产位图装饰。
- 保存最终提示词、工具暴露的模型名称、源输出、发布路径和人工检查结果。

工具未暴露模型名称时记录“未暴露”，不得猜测。

## 8. PPTist 语义协议

### 8.1 顶层要求

- 画布为 `1000 × 562.5`。
- 顶层包含 `width`、`height`、`theme` 和 `slides`。
- 页面 ID 和元素 ID 全局唯一。
- 图片使用 `/api/data/<filename>`，JSON 不内嵌 Base64 大图。
- 只有测试证明现有公共能力不足时才修改渲染器。

### 8.2 页面与文字槽

每页必须标注为 `cover`、`contents`、`transition`、`content` 或 `end`。

| 槽位 | 用途 |
|---|---|
| `title` | 页面主标题 |
| `content` | 副标题、章节说明或长正文 |
| `item` | 目录项或内容项正文 |
| `itemTitle` | 内容项标题 |
| `itemNumber` | 目录项或内容项编号 |
| `partNumber` | 章节编号 |
| `subtitle` | 图片说明或次级标题 |

同一内容组的编号、标题、正文和关联形状必须使用相同 `groupId`。内容不足时删除整个未使用组，不能留下孤立编号、连线或装饰。

### 8.3 图片槽

- 可替换图片使用 `imageType: "content"`。
- 背景和固定装饰使用 `imageType: "decoration"`。
- 内容图片不得与背景、星环、光晕或文字合并为不可拆分大图。
- 装饰图片默认锁定，内容图片保持可选中。
- 内容图片槽不得复用装饰的 `groupId`。
- 无图片输入时移除或安全隐藏整个内容图片槽。
- 内容图片必须携带原始宽高并按安全规则裁剪。

## 9. 开发任务

| 阶段 | 开发任务 | 交付物 | 自动检查结果 |
|---|---|---|---|
| G0 预检 | 检查 Git、重新扫描模板 ID、确认文件范围和服务归属 | 基线记录、最终模板 ID | 不覆盖用户修改，ID 无冲突 |
| G1 审计 | 盘点 25 页、媒体、字体、音频和图表，确定页面映射 | 权利审计、页面映射 | 每页保留、重构或排除动作明确 |
| G2 素材 | 固化视觉规范，生成并检查 4 个 MVP 素材 | 发布素材、生成记录 | 尺寸、Alpha、版权和体积符合 manifest |
| G3 MVP | 制作 1 封面、6 目录、1 章节、3 内容、1 结束 | 12 页设计稿 | 页面可编辑，无示例内容和未授权素材 |
| G4 标注 | 标注页面、文字、图片和 `groupId`，导出 JSON 和封面 | `template_16.json`、`template_16.jpg` | JSON 可读取，无空槽、重复 ID 和 Base64 大图 |
| G5 接入 | 注册模板，新增专项测试并运行受影响回归 | 注册代码、测试摘要 | 新模板可读，现有模板不回归 |
| G6 QA | 真实生成、编辑、换图、四视口检查、导出和重导入 | QA 截图、真实任务和往返摘要 | 主流程通过，按钮反馈完整 |
| G7 扩展 | 增加第二封面、章节、3 个内容和第二结束页 | 18 页生产模板 | 新版式可到达且不破坏 MVP |
| G8 验收 | 复跑受影响测试和真实流程，汇总限制和证据 | 最终验收报告 | 自动检测无问题后进入 `READY_FOR_CONFIRMATION`；人工确认后闭合 |

G0～G7 不设置逐阶段人工确认。每个阶段满足自动检查结果后，执行者自动记录 `PASS` 并继续；检查失败时自动修复、重试和更新证据。只有真正阻断、需要外部授权或 G8 最终闭合时才暂停请求用户输入。

实施 G6 前必须先确认端口、PID、命令行、工作目录和项目归属，只启动缺失的最小服务集合。

### 11.2 真实流程

### 11.4 最终自动验收条件

完成前必须满足：

- 模板 JSON、封面和引用素材存在且可读取。
- MVP 12 页和生产版 18 页数量正确。
- 目录容量、内容分页、标题适配和图片语义通过。
- 18 页无文字越界、异常换行、拉伸、遮挡和破图。
- 专项测试及受影响回归通过。
- 真实生成、编辑、换图、设备适配和 PPTX 往返取得新鲜证据。
- 参考媒体未原样进入生产集合。
- 每个新位图都有提示词、工具、发布路径和人工检查记录。
- 失败、偏差和已知限制如实记录。

自动检查和人工 QA 全部完成且没有问题后，状态只能进入 `READY_FOR_CONFIRMATION`。此时执行者应提交最终报告并停止闭合操作；未收到用户明确的“确认完成”或同等含义回复时，必须保持待确认状态，不得标记 `DONE`。用户明确确认后，才可以执行闭合并设置为 `DONE` 或用户接受限制后的 `DONE_WITH_CONCERNS`。

## 12. 主要风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 参考媒体授权未知 | 商业发布风险 | 原媒体全部排除，重新生成原创抽象素材 |
| 原生图表导入失败 | PPTX 无法稳定导入 | 首版排除，未来用支持的可编辑形状重构 |
| 与“科技蓝扁平”相似 | 模板列表差异不足 | 强化星环、轨道和深空纵深，减少通用网络元素 |
| 星空背景过于嘈杂 | 正文可读性下降 | 中央低细节、边缘装饰、限制星点密度和亮度 |
| 内容图与装饰混组 | 换图时破坏视觉 | 严格区分 `content` 和 `decoration`，不共享分组 |
