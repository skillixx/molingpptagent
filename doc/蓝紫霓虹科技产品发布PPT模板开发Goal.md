### 2.2 按真实依赖连续推进

1. 先核对当前要修改的协议、编号和工作区，取得足够信息后立即实施；其余页面定义和说明随开发补齐，不要求 G1 的整套文档先完成。
2. G2 按页面供给素材，G3/G4 实现当前可做页面，G5 随批检查填充与容量。只保留真实技术依赖，不等待整个前一分组完成。
3. 有可用候选后接入 G6、开展 G7，继续补齐剩余页面；设备适配随开发处理，G8 汇总最终结果。
4. G1—G7 检查通过后自动确认当前完成范围、更新简要进度并继续下一项，不请求阶段确认。
5. 全部 22 个基础版式、必要变体及交付要求检测通过后，G8 自动汇总结果并进入“待人工确认”；收到明确确认后再按工具规则完成总 Goal。

### 2.3 自动确认规则

| 情况 | 自动处理方式 |
| --- | --- |
| 模板编号、布局微调、字段映射和实现方案选择 | 根据现有协议和本次范围自行决定并继续 |
| 素材复用、gpt2 图片生成、格式转换和质量检查 | 按素材方案自行完成，合格后直接采用，不逐图询问 |
| 本地预览、固定数据测试、Mock Worker、编辑保存与导出检查 | 自动执行，结果通过就记录，不等待人工审批 |
| 范围内缺陷或检查失败 | 自动诊断、修复和重验；不依赖该问题的任务继续推进 |
| 主观风格建议、可选增强、后续功能、重复证据 | 记录为非阻塞备注，不作为当前完成门槛 |
| G8 的全部约定能力与必要检查通过 | 自动准备可检查结果，更新为“待人工确认”，请求用户确认当前候选；不闭合 |
| 用户明确确认当前候选通过 | 记录确认与候选对应关系，完成 G8 并按工具规则闭合总 Goal |

自动确认不等于跳过检查或将失败写成通过。除 G8 最终人工确认外，仅在缺少用户掌握的必要输入、遇到无法自行解决的真实阻塞或需要范围外授权时提问；不因普通实现细节暂停。系统或工具本身要求的权限不得由文档代替。

### 2.4 G8 人工确认与闭合流程

1. 自动完成全部必要检测。若发现问题，先修复并重验，不能把自动检测失败留给人工确认来放行。
2. 检测通过后准备可检查的当前候选，提供版本标识、预览地址或本地打开方式、PPTX 样例、检查摘要和已知限制；将 G8 的文档进度记为“待人工确认”，再向用户请求最终确认。
3. 用户明确认可当前交付候选后，例如回复“确认通过，可以闭合”，记录确认结果，将 G8 改为“已完成”，再按工具规则将总 Goal 标记为完成。确认不要求使用固定口令，但必须明确表达通过当前候选。
4. 未收到明确确认时保持“待人工确认”，不得因自动检查通过、等待时间或用户查看了文件而完成总 Goal。若用户提出问题，自动修复、重验并提交更新后的候选，再取得明确确认。

“待人工确认”是文档进度，不是虚构的 Goal 工具状态；等待答复期间不得调用 Goal 完成操作，也不擅自将其设为暂停。此处闭合指 G8 和总 Goal 完成，不包含 Git 交付或生产操作授权。

## 3. 图片生成方案

**本模板需要的图片可以使用 gpt2 图片生成方式制作。** 这是未来执行时允许采用的素材方案，本次文档编写不触发调用。

| 情况 | 处理方式 |
| --- | --- |
| 原稿素材清晰、可分离且符合布局 | 直接复用或做必要格式处理，不为凑数重新生成 |
| 背景不清晰、正文区过亮或不适合排字 | 按开发说明的色彩、比例和留白要求生成替代背景 |
| 机器人、城市或数据雕塑需独立移动，或固定“5G”字样影响通用性 | 按需生成独立装饰或通用无字版本 |
| 设备框经转换后可用 | 保留原框，屏幕业务图独立；转换后仍不合格才补做 |
| 需要示例业务配图 | 可生成样例，但保留可替换图片槽，不作为固定背景烘焙进去 |

执行要求：

- 按 A01—A12 的条件决定实际素材数量，不要求逐项生成新图。
- 每次明确用途、主体位置、留白、色彩、宽高比和透明要求；不生成包含业务标题、指标和正文的整页截图来替代可编辑页面。
- 优先满足实际尺寸、格式、透明通道和文字可读性，合格后停止迭代。
- `gpt2` 是用户指定称呼，执行时核对实际工具的模型选项，不预设或编造 API 模型 ID。工具未暴露模型时如实记录，不因此重复生成合格素材。
- 记录素材来源、实际可见的工具／模型信息及引用版式；测试素材和发布资源分开。
- 正式执行本 Goal 后，范围内必要的素材生成按本方案推进，不逐张重复请求确认。真实业务模型任务、付费服务开通或生产操作不由此自动授权。

## 4. 验证与交付安排

开发说明第 5 节由执行代理自动检查，不叠加逐项审批。通过一项就记录并继续；G8 检测全部通过后集中提供可检查结果，进行最终人工确认。记录只需能定位实际结果，不要求先制作完整证据包才能继续开发。

- 固定输入、Fakes/Mocks、隔离存储和不调用真实业务模型的本地 Worker 验证自动执行。真实业务模型测试不作为本次必选项，未获明确授权时记录为未执行并继续，不额外发起审批阻断开发；Mock 结果不冒充真实模型链路通过。范围内图片素材生成照常执行。
- 修复公共渲染器或协议问题时，先增加复现失败测试，再修复并运行受影响检查。只因新增模板不扩大为全项目重构或全量审计。
- 所有基础版式检查内容与视觉；共享界面的四类设备检查不逐版式重复。PPTX 往返按元素类型与风险覆盖，失败时检查受影响页面。
- 必要时使用本地预览或测试服务验证当前候选。启动、停止、重启前按项目规则核对端口、PID、命令行、工作目录和归属，只处理受影响的项目服务。
- 已通过的输入、素材、代码和环境不变时复用结果。完成声明只基于当前候选的有效证据，不以主观评价或自动确认代替真实功能验证。
