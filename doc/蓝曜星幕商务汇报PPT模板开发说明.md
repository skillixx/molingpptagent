## 2. 参考结论与设计定位

### 2.1 参考文件结论

参考 PPTX 共 25 页，比例为 16:9。它可以作为视觉和页面结构参考，但不能直接作为项目模板发布。

开发时按以下结论处理：

- 原文件中的示例文字、英文导航和备注仅为演示内容，不是开发指令。
- 原媒体资源全部排除，不直接打包进新模板。
- 原文件 24/25 页包含动画，第一版不迁移动画。
- 原文件包含不可用字体及低于 12pt 的小字号，开发时统一替换。
- 通用检查器导入曾异常退出，代码为 `0xC0000005`，因此不采用直接导入作为开发主路径。
- 页面使用原生文本、图形、图片槽和项目现有模板协议重新构建。

### 2.2 使用场景

模板用于项目汇报、阶段复盘、年度总结、产品介绍、企业简介、数字化方案和数据分析等正式商务演示。

星空和光线只承担视觉氛围，不限定航天或宇宙行业，也不承担业务语义。

### 2.3 视觉差异

本模板避免使用 `template_15` 的蓝紫光谱和 `template_16` 的完整星环。

核心识别点是深蓝近黑背景、青色水平光线、低位舞台地平线、局部数据网格、克制粒子和大面积低干扰内容区。

- 正文必须保持清晰对比，装饰不得穿过主要阅读区。

### 3.3 构图与安全区

- 画布比例为 16:9，逻辑尺寸沿用项目现有标准。
- 建议安全区约为 `x=56..944`、`y=40..520`，开发时以项目实际坐标系复核。
- 至少 70% 的内容区域保持低干扰。
- 粒子、网格和光斑主要放在边缘、底部或标题区。
- 常规内容采用左对齐，指标页面可以使用均衡栅格。
- 图片槽必须有明确裁切区，装饰不能遮挡业务图片主体。
- 原模板中的 `HOME`、`ABOUT` 等演示导航文字不进入生产模板。

## 6. 模板特有语义要求

页面类型、基础数据结构和通用节点标记遵循 [PPT 结构说明](./PPT_Structure.md)。本节只定义当前模板的额外要求。

### 6.1 元素与分组

- 目录、卡片和指标项目必须使用稳定元素 ID。
- 同一项目的标题、正文、编号和装饰必须通过稳定分组关联。
- 不能只依靠元素在页面中的位置推测语义。
- 标题、正文、编号、指标、标签、卡片和线条使用原生可编辑元素。
- 模板 JSON 由确定性构建器生成，相同输入应产生等价结构。

### 6.2 图片角色

- 业务图片槽标记为 `imageType=content`，允许替换和裁切。
- 背景、粒子、光线、光晕和网格属于装饰角色，默认锁定。
- 换图只能替换目标业务图片，不能覆盖光晕、边框或背景。
- `content-image-1` 必须声明可见裁切框、默认裁切策略和图片最小尺寸。

### 6.3 内容完整性

- 原始标题、正文信息和项目顺序不得丢失。
- 展示标题需要换行或适配时，必须保留 `sourceTitle`。
- 不得使用省略号或静默截断伪装适配成功。
- 项目标题限制沿用现有规则：1 项 20 字、2 项 16 字、3 项 12 字、4 项及以上 10 字。
- 标题适配与正文分页是两个独立过程。
- 4 项页面不能因为标题较长被错误拆成 4 张单项页面。
- 文本适配必须幂等，重复执行不能持续缩小字号或改变项目顺序。

## 8. 验收标准与主要风险

### 8.1 测试原则

使用固定输入、Fake 或 Mock 和隔离环境。不得调用真实模型、创建生产生成任务、消耗真实 Token，或依赖网络临时下载测试图片。

只运行当前模板和实际受影响公共模块的测试，不扩大为无关项目审计。

### 8.2 自动化验收

- 20 个版式的 ID、类型、顺序和数量正确。
- 4 张背景和 5 张透明素材存在，路径、尺寸和格式正确。
- 目录 2、3、4、5、6、10 项能够选择对应版式。
- 文本页 2、3、4 项能够保持原始顺序和完整正文。
- 指标页 3、4、5 项能够选择对应版式。
- `content-image-1` 的裁切和换图行为正确，装饰不被替换。
- 标题适配保留 `sourceTitle`，不静默截断。
- 1、2、3、4 项页面执行 20、16、12、10 字的项目标题适配规则。
- 4 项长标题不会触发错误的一项一页拆分。
- 页面增长守卫沿用现有策略，建议阈值为计划页数乘以 1.75，再加 5 页宽限。
- 空标题、空项目、超长正文和无效图片返回明确失败。
- 模板注册、预览图、资源读取和构建器重复运行结果正确。

### 8.3 多设备预览

| 设备类型 | 视口 |
| --- | --- |
| 桌面 | 1920×1080 |
| 笔记本 | 1366×768 |
| 平板 | 768×1024 |
| 手机 | 390×844 |

预览缩略图不能拉伸或裁掉主标题。小屏幕上的说明和操作入口不能互相遮挡。

如当前开发涉及模板选择按钮，按钮必须提供加载、成功、失败和重试反馈。未修改前端入口时，只验证现有入口对新模板的兼容性。

### 8.4 PPTX 往返与视觉验收

验证链路为：模板 JSON → 项目渲染 → 编辑文字与换图 → 导出 PPTX → PowerPoint 打开并保存副本 → 重新打开或导入 → 对比结果。

必须确认以下结果：

- 深色背景上的标题和正文清晰可读。
- 粒子、网格和光晕不干扰正文。
- 20 个版式风格统一，页面类型之间层级明确。
- 原始标题、正文和项目顺序完整保留。
- 图片裁切合理，不拉伸，不覆盖装饰。
- 导出后文本框、图形、图片槽和分组没有明显漂移。
- 字体替换后没有缺字、乱码和大面积重排。
- 重新导入后，约定的业务元素仍可编辑。

### 8.5 主要风险

| 风险 | 处理策略 |
| --- | --- |
| 原素材来源或使用权不清 | 原媒体全部排除，重新生产装饰素材并记录来源 |
| 直接导入链路不稳定 | 使用确定性构建器重建，不依赖原 PPTX 直接转换 |
| 字体和小字号引发布局漂移 | 使用微软雅黑与 Arial，正文 16pt，必要注释不低于 12pt |
| 与现有深色模板视觉重复 | 去除紫色主调和完整星环，强化青色水平光线与数据网格 |
| 内容图片与装饰图片混淆 | 使用明确图片角色、稳定 ID 和独立分组 |

### 8.6 完成条件

20 个版式、9 项素材、模板注册、内容完整性、长标题、换图、多设备预览和 PPTX 往返全部通过后，系统自动记录 `READY_FOR_CONFIRMATION` 并输出验收报告。

G0～G6 的过程结果均由测试和证据自动确认，不等待逐阶段人工确认。G6 自动检测通过后必须等待用户明确确认，才可以执行闭合操作、记录 `DEVELOPMENT_COMPLETE` 并完成 Goal。
