### 2.2 视觉和排版

封面与结束页使用蓝色天空、暖金城市灯光；章节页使用建筑或会议剪影，中央放置菱形框；目录使用低对比星云；正文使用黑色或深蓝背景、蓝色强调和浅色文字。

| 项目 | 实施初值 |
|---|---|
| 背景色 | 黑色 `#080B10` 或深蓝 `#101B2C` |
| 强调色 | 色块用 `#1263A5`；深底上的强调文字用较亮的 `#4CBDE3` |
| 文字与分隔线 | 主文字 `#F5F7FA`，次级文字 `#C3CBD6`，分隔线 `#657286` |
| 字体 | 中文优先微软雅黑，英文和数字优先 Arial；确认编辑、导出环境可用 |
| 字号 | 封面 38～52 px，页标题 28～34 px，条目标题 20～24 px；正文优先 18～22 px、最低 16 px |
| 安全区 | 建议 x = 48～952、y = 32～530；长标题预留多行空间 |

色值、字号区间和安全区是排版起点，可按实际渲染调整。正文容量不足时调整布局或分页，不继续缩小到最低字号以下。这里的 px 指逻辑画布尺寸，不与 PowerPoint 的 pt 数值直接混用。

**保持可编辑：**标题、正文、编号、百分比、日期和联系信息使用文字对象；菱形框、标题条、分隔线、流程箭头和时间线使用原生形状；简单图标优先复用已有资源。固定背景不包含这些内容，也不把整页截图作为成品。

### 4.2 内容槽位与图片角色

| 对象 | 标记或要求 |
|---|---|
| 页面 | 使用第 2 节定义的五类页面；每个页面及元素 ID 唯一 |
| 页标题 | `textType: "title"` |
| 条目标题 | `textType: "itemTitle"` |
| 正文和条目 | 按现有协议使用 `textType: "content"` 或 `textType: "item"` |
| 编号 | 按用途使用 `textType: "itemNumber"` 或 `textType: "partNumber"` |
| 同一业务条目 | 标题、正文、编号和对应图片建立稳定分组关系 |
| 可换业务图 | `imageType: "content"`，明确数量与条目对应关系 |
| 固定背景与装饰 | `imageType: "decoration"`，与业务组隔离，避免替换或空槽清理误删 |
| 专项正文 | 复用 `process`、`timeline`、`metrics`、`compare` 布局及既有输入协议 |

本模板已显式启用三个兼容选项：封面页的 `fitTitleBeforeVariant: true` 在自动选版时先匹配完整标题容量；模板级 `unsupportedLayoutPolicy: "ordinary"` 将容量不符的已知专项布局保序降级；`sourceImageCountPolicy: "one-per-item"` 在分页前校验源图片与条目数量。旧模板未声明这些选项时保持原行为。

合并前审查已补充专项文字实际容量和图片槽匹配检查，并修复空指标说明的业务组保留问题。正式版式与素材未变化，新增修正及验证见[远程交付与合并评估](./template_25_merge_readiness.md)；原 T8 确认记录作为历史快照保留。

正式图片从 `/api/data/` 读取，模板 JSON 不引用桌面或临时目录，不嵌入大型 Base64 图片。业务图替换为横图、竖图或方图时，需要重新计算适合图片槽的裁切。

### 4.3 选版、分页和内容保真

1. **稳定选版。** 按页面类型、条目数、业务图片数和指定布局选择页面。两种单图、封面或章节变体复用项目已有机制，相同输入应得到稳定结果。
2. **目录容量。** 2～6 项精确选版；1 项复用两项版式并清理空槽及对应装饰。超过 6 项按顺序分页，例如 7 项为 6＋1，不补造条目。
3. **正文容量。** 普通正文每页最多 4 项，5 项可拆成 4＋1。长正文继续按可读容量拆分，各段拼接后必须保持原文完整。
4. **标题保真。** 保留 `sourceTitle` 等原始标题信息；展示标题发生适配时，原题仍须完整保留在内容中。不得静默截断或用省略号替代。不能仅因条目标题长，就把四项正文拆成四个单项页。
5. **专项布局。** 流程 4 项、时间线 3 项、指标 4 项、对比 2 项。数量不适合时，采用保序续页或通用正文承接；日期、数字、单位、标签和说明都要保留。
6. **图文对应。** 多图与条目一一对应，数量不匹配时明确反馈，不忽略图片或复制图片凑数。带图长正文的续页可用纯文字，原图片仍归属原条目。
7. **有效输入。** 缺失必需内容、空列表和非法输入沿用项目校验；指标值、日期和业务信息来自输入，不补造数据。

### 5.2 自动推进方式

1. 核对模板编号和工作树，落实布局规则；这些检查由执行者直接完成，不设置准备阶段审批。

3. 有效模板 ID、可加载候选 JSON 和实际引用资源具备后，即可进行 T6 的本地注册与预览验证，同时按已实现能力开展 T7、T8，不必等待 T3～T5 全部完成才检查入口。
4. 普通问题自动诊断、修复和重验；某项暂时失败时继续其他不依赖该结果的工作。相关输入、代码和环境未变化时复用有效证据。

自动检查以实际产物和验证结果为依据，失败或未检查项不能视为通过。完整候选统一核对第 6 节，全部满足后记录“T8 自动检测通过，待人工确认”；人工确认前保持 T8 和 Goal 未完成，不执行闭合操作。

1. 自动检测全部通过后，先提供当前候选的可检查入口或交付文件、模板编号、检测摘要、必要截图或 PPTX 往返证据及已知限制，再请求用户确认。已经运行本地候选时，提供经过验证的访问地址。
