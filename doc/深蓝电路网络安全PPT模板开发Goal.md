## 1. Goal 目标

在 `D:\moling\TrainPPTAgent` 中完成“深蓝电路·网络安全”模板，使用户能够选择模板、填充生成内容、编辑文字、替换图片、保存文档，以及导出和重新导入 PPTX。

使用一个开发 Goal 覆盖 T1～T8。T1～T7 自动判断、检查、确认并推进，14 个基础版式不设置单独放行点。T8 自动检测无问题后提交当前候选，等待用户明确确认；收到确认后才执行闭合并完成 Goal。T8 是本 Goal 内唯一的人工验收点。

详细版式、素材规格和内容协议以[开发说明](./深蓝电路网络安全PPT模板开发说明.md)为准。本规划负责执行顺序、任务产物和完成判断；若实际需要改变范围，先说明影响并按用户明确要求调整。

## 3. 图片生成安排

**模板所需图片可以使用 GPT2 图片模板生成。** 后续明确启动开发后，按开发说明的尺寸、构图、格式和透明通道要求制作以下素材，不逐张增加审批。

| 编号 | 素材 | 生成与使用重点 |
|---|---|---|
| A1 | 封面背景 | 深蓝渐变，中央留白，不固化标题和锁形 |
| A2 | 正文背景 | 低对比、正文区域干净 |
| A3 | 章节背景 | 右侧柔和光晕，左侧留给标题 |
| A4 | 结束背景 | 同色系、安静，适合结束语和联系信息 |
| A5 | 锁形装饰 | 青灰色，真实透明通道，缩小后仍清楚 |
| A6 | 右上电路 | 细线与节点向内延伸，透明 PNG |
| A7 | 左下电路 | 与 A6 保持线宽、节点及色系一致 |
| A8 | 节点网络球 | 低亮度、轮廓完整、无业务标签，透明 PNG |

- 必要的业务展示样例图也可采用该方式，但与固定装饰分开管理，不扩大 A1～A8 库存，不替代用户上传的业务图。
- 素材可从统一基础画面派生，按页面需要分批制作；放入实际页面检查，满足用途后停止迭代。
- 记录来源、版本、尺寸、用途及检查结果。工具未暴露实际模型名称时记录“工具未暴露”，不得声称已验证底层模型为 GPT2，也不因此重复生成。
- 文字、指标数值、流程节点及业务关系保持可编辑，不将这些内容合成为整页图片。
- 固定输入和 Fake/Mock 用于内容填充、分页等验证；这一方式不禁止本节明确允许的图片生成。真实文本或大纲模型调用、生产生成任务不属于本 Goal 的默认验证要求。

T6 的注册和正式资源指项目本地代码中的模板接入，不表示生产部署。后续若需运行候选程序，核对工作目录、代码版本及服务归属，只启动或重启实际需要的项目服务。

## 5. 自动推进与 T8 人工确认

1. 开发范围内的排版、字体适配、素材批次、实现方式及普通缺陷修复，由开发者自行判断并执行，不请求逐项批准；仅 T8 最终闭合设置“待人工确认”。
2. T1～T7 有效检查通过后自动确认完成并继续。T8 自动检测通过后只记录检测结果和待确认状态，不得标记 T8 已完成或将实际 Goal 标记为完成。
3. 普通缺陷自动修复并重验，同时继续不受影响的工作。真实功能失败、内容丢失或导出不可用不能被自动确认掩盖；未执行的检查仍记为未执行。
4. 进度记录保留当前状态、产物路径及必要检查结果；T8 闭合时补充用户确认依据和对应候选。直接维护任务表即可，不要求逐项签字或另建审批文件。
5. 输入、代码和环境未变化时复用有效证据；主观风格差异、底层模型名称未暴露、历史模板问题以及其他范围外事项不阻塞当前开发，也不反复触发重做。
6. 除 T8 必须进行的最终人工确认外，只有缺少不可替代输入、遇到无法自行解决的外部问题或需要范围外授权时才提出具体需要。此前继续独立工作；实际 Goal 状态遵循工具规则。

任务表中的状态是文档记录，不代替实际 Goal 状态。当前实际进度见上表，证据与运行记录见 `doc/assets/template_26_qa/`。

## 6. T8 检测、人工确认与闭合

开发者先依据当前候选自动检查以下三类交付结果。它们可合并检查，不设置三次独立审批；全部满足后统一提交 T8 人工确认。

| 交付结果 | 自动核对内容 |
|---|---|
| 库存与资源完整 | 基础 14 个版式保留，完整库存共 22 个唯一页面 ID；A1～A8 齐全且符合用途，透明装饰和正式资源引用有效 |
| 核心使用流程可用 | 可选择、填充、编辑、换图裁切、保存重开及 PPTX 导出再导入；标题、正文、数字、单位和顺序完整；单/多图及专项布局正确，不因标题长拆散四项页，固定装饰不被覆盖 |
| 适配与交付齐全 | 受影响入口覆盖桌面、笔记本、平板和手机，修改按钮反馈明确；构建器、JSON、封面、素材、必要测试与样例齐全，结果对应当前候选 |

T8 按以下流程处理，闭合仍属于 T8，不新增 T9：

1. **自动检测。** 三类结果无问题，且必需功能和检查均实际完成，才进入人工确认；发现缺陷自动修复并重验，不能把失败或未执行项记为通过。
2. **准备候选。** 提供模板编号、候选代码版本或变更标识、可检查的程序或样例、导出文件、必要检测结果和实际限制。需要运行程序时先准备并验证访问地址，再请求确认。
3. **等待人工确认。** 将 T8 记为“待人工确认”，明确请用户确认该候选是否完成。Goal 保持未完成；自动检测通过、用户沉默或等待超时均不代表人工确认。
4. **执行闭合。** 收到用户对当前候选明确的“确认完成”或等效验收答复后，记录确认依据及候选标识，更新开发说明和 Goal 任务表，将 T8 标记为“已完成”，再将实际 Goal 标记为完成。
5. **处理反馈。** 用户提出修改时，修复并重验受影响部分，更新候选后重新提交人工确认。未变化部分复用有效证据，不重复全量验收。

闭合只包括验收记录、任务状态和 Goal 完成状态的更新；不包含 Git 提交、推送、PR、合并或生产操作。

固定输入经过实际模板填充链路得到有效结果，可以验证模板生成能力；本文不将真实文本模型调用作为完成条件。图片生成按照第 3 节执行。
