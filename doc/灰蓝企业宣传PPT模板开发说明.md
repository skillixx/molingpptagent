# 灰蓝企业宣传 PPT 模板开发说明

> 状态：`IMPLEMENTED / DONE`
> 候选模板 ID：`template_13`
> 模板名称：`灰蓝企业宣传`
> 参考文件：`企业宣传(20).pptx`（本地参考文件，不入库）
> 本文记录已完成实现的开发范围和验收标准；最终实现与证据以 Goal 和素材与 QA 记录为准。

## 1. 开发目标与边界

### 1.1 开发目标

基于参考 PPT 的灰蓝主色、暖米金点缀、建筑切面和非对称图文构图，为 TrainPPTAgent 新增一套企业宣传类生产模板。

模板面向企业介绍、产品方案、项目汇报、招商合作和年度总结，必须支持：

- 封面、目录、章节、内容和结束五种页面类型；
- 2、3、4、5、6、10 项目录精确选版；
- 1～4 项普通内容、单图文和双图文页面；
- 超量内容和超长正文自动分页，且不丢字、不乱序；
- Agent 内容图片与固定背景、装饰图片严格隔离；
- 在线编辑、图片替换、PPTX 导出和重新导入；
- 桌面、笔记本、平板和手机端正常操作；
- 所有可见按钮都有加载、成功、失败或假性交互反馈。

### 1.2 开发范围

- 审计参考 PPT 的页面、字体、图片、图表和版权风险。
- 建立参考页面与 12 页 MVP、18 页生产模板的映射。
- 固化画布、颜色、字体、字号、间距和内容安全区。
- 生产并引用 6 项原创背景和透明装饰素材。
- 使用 PPTist 可编辑元素重建动态文字、编号、卡片、分隔线和图片框。
- 完成页面、文字、图片和内容分组的语义标注。
- 注册模板资源并增加结构、容量、分页、图片和接口专项测试。
- 完成真实生成、多设备、PPTX 导出和重新导入 QA。

### 1.3 不在本次范围内

- 不直接发布参考 PPT 或其中授权不明确的图片、字体和 Logo。
- 不生成假 Logo、假产品界面、假证书、假业务数据或可识别真人。
- 不为本模板增加私有 Agent 数据协议。
- 不重写 PPTist 编辑器或模板渲染器架构。
- 不在没有测试证据时修改渲染器或前端。
- 不主动提交、推送、创建 PR、合并或部署。

### 2.3 重建原则

- 保留构图比例、视觉重心和留白节奏，不复制未授权素材。
- 动态文字、编号、色块、分隔线和基础几何使用 PPTist 原生元素。
- 照片框从形状填充中拆出，建立独立的内容图片槽。
- 固定背景和装饰保持锁定，不能被 Agent 图片替换。
- 不保留用途重复、容量不明确或无法稳定自动填充的页面。
- V1 不移植原稿图表，避免不兼容标记和来源不明样式进入生产链路。

### 3.1 12 页 MVP

MVP 用于验证“语义数据 → 选版 → 内容填充 → 在线编辑 → PPTX 导出 → 重新导入”的完整链路。

| `contents-2` | `contents` | 2 项目录 | 第 2 页派生 |
| `contents-3` | `contents` | 3 项目录 | 第 2 页派生 |
| `contents-4` | `contents` | 4 项目录 | 第 2 页 |
| `contents-5` | `contents` | 5 项目录 | 第 2 页派生 |
| `contents-6` | `contents` | 6 项目录 | 第 2 页派生 |
| `contents-10` | `contents` | 10 项目录 | 第 2 页派生 |
| `transition-facet` | `transition` | 深色章节页 | 第 3 或 10 页 |
| `content-text-2` | `content` | 2 项正文 | 第 6 或 24 页 |

`metadata.mvpSlideIds` 必须精确包含以上 12 个页面 ID。

MVP 未通过真实生成、长文本、图片保护、编辑和 PPTX 往返测试前，不扩展生产版。

| `content` | 6 | 单结论、2项、3项、4项、单图文、双图文 |

### 3.3 选版与分页

- 目录严格按 2、3、4、5、6、10 项选择精确容量页面。
- 一项普通内容选择 `content-statement-1`。
- 二、三、四项普通内容分别选择对应容量的纯文字页面。
- 一项内容加一张图片选择 `content-image-1`。
- 两项内容加两张图片选择 `content-image-2`。
- 无图片输入时优先选择纯文字页面，不显示空图片框。
- 图片数量与内容项数量不匹配时明确失败，不丢图、不跨项错配。
- 超过四项的普通内容按最大容量分页，项目顺序保持不变。
- 超长正文分页后不得丢字；带图长正文只在第一段保留一次图片。
- 两种封面、章节和结束页必须能通过确定性种子分别选中。

## 4. 视觉规范

### 4.1 视觉定位与颜色

| 项目 | 规范 |
|---|---|
| 视觉关键词 | 灰蓝、暖米金、建筑感、克制、专业、轻质感 |
| 构图倾向 | 大标题、非对称图文、边缘折面、清晰编号、稳定留白 |
| 禁止方向 | 过度科技霓虹、重拟物、卡片堆叠、满版装饰、伪品牌视觉 |

| 用途 | 色值 |
|---|---|
| 灰蓝主色 | `#455273` |
| 深灰蓝 | `#313A51` |
| 次级灰蓝 | `#5C6E9A` |
| 暖米金强调色 | `#F0D3A9` |
| 浅灰背景 | `#F4F6F8` |
| 主文字 | `#222B35` |
| 次文字 | `#687386` |
| 反白文字 | `#FFFFFF` |

暖米金只用于编号、细线、小面积折面和视觉焦点。警示红只用于真实风险或负向数据，不作为常规装饰色。

### 4.2 字体和字号

- 中文动态文字统一使用微软雅黑，或项目确认可部署的思源黑体。
- 英文和数字使用 Arial，或与中文统一使用微软雅黑。
- 不依赖参考稿中的方正兰亭黑简体、华文黑体和历史兼容字体。
- 固定背景和装饰图不得包含文字。

| 文本角色 | 最低字号 |
|---|---:|
| 封面标题 | 50px |
| 页面标题 | 35px |
| 内容项标题 | 24px |
| 正文、目录项和联系方式 | 16px |
| 自动缩字硬下限 | 12px |

文字超出容量时优先分页或换版，不允许低于 12px，也不允许静默截断。

### 4.3 画布和安全区

| 区域 | 规范 |
|---|---:|
| 逻辑画布 | `1000 × 562.5` |
| 左右安全边距 | 55px |
| 上下安全边距 | 42px |
| 页面标题区高度 | 80～100px |
| 封面连续标题区 | 至少画布宽度的 52% |
| 装饰最大边缘侵入 | 140px |
| 装饰与正文最小间距 | 24px |
| 内容图片与正文最小间距 | 24px |

页面标题默认保持单行。装饰的实际不透明边界不得进入标题、正文和内容图片槽。

### 5.2 素材生产要求

- 每张素材使用独立提示词生成，不制作素材拼图。
- 位图使用图片生成工具或授权明确的来源，不使用 Python 或程序化绘图生成装饰图。
- 背景使用 JPG，透明装饰使用具有真实 Alpha 通道的 PNG。
- 素材不得包含文字、数字、Logo、水印、真实品牌、真实产品界面或人物。
- 背景必须预留标题安全区，中心区域保持低干扰。
- 透明素材需要在深色和浅色背景上检查白边、灰底和矩形边缘。
- 每项素材保存提示词、工具、模型、原始输出、发布路径和人工检查结果。
- 未被 `template_13.json` 引用的素材不得进入生产目录。

### 5.3 必须保持可编辑的元素

以下内容使用 PPTist 原生元素，不制作成位图：

- 斜切色块、矩形背景、细线和分隔线；
- 目录编号、章节数字、页码和圆点；
- 内容卡片、图片框、圆环、指标和进度条；
- 三角形、多边形、图片遮罩和半透明蒙层；
- 简单流程线、时间轴和步骤节点；
- Logo 占位区域。

没有真实 Logo 时采用无 Logo 版式。企业、产品和行业照片不固化在模板中，统一作为运行时内容图片进入独立图片槽。

## 6. PPTist 语义和 JSON 契约

### 6.1 页面和文字角色

生产模板只使用 `cover`、`contents`、`transition`、`content`、`end` 五种页面类型。

| 文字角色 | 用途 |
|---|---|
| `title` | 封面、页面、章节和结束页标题 |
| `content` | 封面副标题、章节说明、单结论正文和结束页正文 |
| `item` | 目录项或内容项正文 |
| `itemTitle` | 内容项标题 |
| `itemNumber` | 目录项或内容项编号 |
| `partNumber` | 章节编号 |
| `subtitle` | 图片说明或次级标题 |

文本槽可以是文本元素，也可以是带文字的形状。同一内容项的 `itemTitle`、`item`、`itemNumber` 和伴随装饰形状必须使用一致的 `groupId`。

内容不足时删除整个未使用分组，不能留下空编号、空卡片或孤立装饰。

### 6.2 图片角色

- Agent 或用户可替换图片使用 `imageType: "content"`。
- 背景和固定装饰使用 `imageType: "decoration"` 或项目支持的背景类型。
- 装饰图锁定，不参与 Agent 图片替换。
- 内容图保持可选中、可替换，不与装饰或文字合并。
- 内容图不设置内容项 `groupId`，避免参与文本组复制和删除。
- 单图文、双图文页设置 `strictImageCount: true`。
- 内容图片设置 `requireSourceDimensions: true`。
- 图片使用中心裁切，不能拉伸填满容器。
- 无图片输入时不得显示破图、默认照片或空图片框。

### 6.3 `template_13.json` 硬约束

- 模板 ID 为 `template_13`，名称为“灰蓝企业宣传”。
- 画布为 `1000 × 562.5`，页面总数为 18。
- 页面类型数量为 2 个封面、6 个目录、2 个章节、6 个内容、2 个结束页。
- `metadata.mvpSlideIds` 精确包含第 3.1 节定义的 12 个页面 ID。
- `metadata.aspectRatio` 为 `16:9`。
- `metadata.sourceReference` 记录 `企业宣传(20).pptx`。
- `metadata.imageSlotMarker` 记录 `imageType=content`。
- `metadata.decorativeImageMarker` 记录 `imageType=decoration`。
- 页面 ID 和元素 ID 全局唯一。
- 图片统一使用 `/api/data/` 地址，不内嵌 Base64 大图。
- JSON 不包含本机绝对路径、临时目录、参考稿示例文字和来源标记。
- 每页 `remark` 保存 `[Sources]` 来源块。
- JSON 文件目标体积小于 1MB。

### 7.4 构建要求

- 构建脚本使用 JavaScript ES Module，关键逻辑使用中文注解。
- 构建过程可重复、确定，不依赖临时目录和本机绝对路径。
- 可以复用现有模板的数据骨架，但必须生成专属 ID、颜色、素材和元数据。
- 动态文字和基础几何保持可编辑，不能用整页截图代替模板页面。
- 构建后检查 ID、资源引用、路径、JSON 体积和示例文案残留。
- 如果新增或修改前端按钮，必须实现可见反馈并完成多设备适配。

## 8. 验收、风险与完成定义

### 8.1 结构和文字

- 页面总数为 18，类型数量为 2/6/2/6/2。
- 12 页 MVP ID 存在且唯一，页面和元素 ID 全局唯一。
- 6 项核心素材全部被引用，没有未引用的模板素材。
- 模板封面为 960×540 RGB JPEG，体积小于 350KB。
- JSON 小于 1MB，不含本机路径、Base64 大图和参考示例文字。
- 封面标题不低于 50px，页面标题不低于 35px。
- 内容项标题不低于 24px，正文和目录项不低于 16px。
- 自动缩字不低于 12px，超出容量时分页而不是截断。

建议内容边界：

| 内容 | 边界 |
|---|---:|
| 页面标题 | 最长 40 个中英文混排字符 |
| 内容项标题 | 最长 30 个字符 |
| 目录项 | 每项最长 14 个中英文混排字符 |
| 1 项正文 | 最长 90 字，超出允许分页 |
| 2 项正文 | 每项最长 90 字，超出允许分页 |
| 3 项正文 | 每项最长 60 字，超出允许分页 |
| 4 项正文 | 每项最长 45 字，超出允许分页 |

### 8.2 选版、分页和图片

- 目录按 2、3、4、5、6、10 项精确选版。
- 1～4 项普通内容选择正确容量页面。
- 无图片内容不选择图文页。
- 一张和两张图片分别选择单图文、双图文页。
- 8 项内容分页后顺序不变。
- 长正文分页后字符完整，带图长正文只保留一次图片。
- Agent 图片只进入 `imageType: "content"` 槽。
- 固定背景和装饰保持 `/api/data/template_13_asset_*` 路径。
- 图片数量不匹配、缺少图片槽或缺少源图尺寸时明确失败。
- 横图、竖图和方图保持容器比例中心裁切，不发生拉伸。

### 8.3 视觉、设备和交互

| 设备 | 代表视口 |
|---|---|
| 桌面 | 1920×1080 |
| 笔记本 | 1366×768 |
| 平板 | 768×1024 |
| 手机 | 390×844 |

- 18 页逐页检查，无文字溢出、异常换行、重叠、破图和装饰遮挡。
- 预览画布保持 16:9，模板卡片有明确选中状态。
- 手机端模板列表可滚动，预览、返回和下载入口可触达。
- 加载、成功、失败、重试、替换图片、下载和导出都有可见反馈。
- 暂时只能提供假性交互的按钮也必须显示状态，不能点击后无反应。
- 浏览器控制台没有模板相关未处理错误。

### 8.4 PPTX 和回归

- 真实生成作品可以导出 PPTX 并正常打开。
- 导出前后页面数量一致。
- 导出的 PPTX 可以重新导入并继续编辑文字和内容图片。
- 字体、换行、图片裁切和装饰位置没有明显漂移。
- `template_1`～`template_12` 的关键能力无回归。
- 如果修改前端，类型检查、单元测试和生产构建必须通过。

### 8.5 主要风险

| 风险 | 处理策略 |
|---|---|
| 参考稿版权不明确 | 只保留构图关系，背景、照片和装饰使用原创或授权素材 |
| 非标准字体导致排版变化 | 动态文字统一使用项目可部署字体，并检查导出换行 |
| 图片以形状填充存在 | 拆分为独立内容图槽，装饰和内容分别标记 |
| 原稿图表标记不兼容 | V1 不移植原图表，未来按真实数据需求重建 |
| 装饰被 Agent 配图覆盖 | 使用 `imageType`、资源路径和专项测试三重保护 |
| 长文本破坏版式 | 按真实槽位容量分页，不降低到最小字号以下 |
| 移动端操作受阻 | 使用四种视口验证，只做有证据的最小前端修复 |

### 8.6 完成定义

以下条件全部满足后，模板进入 `READY_FOR_CONFIRMATION`：

- 12 页 MVP、18 页生产模板和 6 项素材全部完成。
- 专项测试、受影响后端回归和必要的前端检查通过。
- 真实生成、编辑、换图、失败重试、PPTX 导出和重新导入通过。
- 四种设备视口和 18 页逐页视觉检查均有证据。
- 素材来源、提示词、授权、测试结果和已知限制记录完整。

自动验收通过后等待用户进行唯一一次最终人工确认。只有用户明确确认后，才能调用 Goal 完成工具并闭合为 `DONE / complete`。
