九、PPTist 语义协议
- 页面类型只使用 cover、contents、transition、content、end。
- 文字槽使用 title、content、item、itemTitle、itemNumber、partNumber、subtitle。
- 同一内容组的编号、标题、正文和关联形状使用相同 groupId。
- 内容不足时删除整个未使用组，不能留下孤立编号、连线、卡片或装饰。
- 可替换业务图片使用 imageType: content。
- 背景、世界地图和菱形装饰使用 imageType: decoration 并锁定。
- 内容图片不得与装饰共用 groupId，也不得与背景或文字合并成一张图。
- 内容图片必须携带原始宽高，并验证横图、竖图和方图裁切。
- 图片统一通过 /api/data/<filename> 引用，JSON 不内嵌 Base64 大图。

十、代码和测试
- 新增代码使用中文注释解释非显然逻辑。
- 先验证现有渲染器，只有测试证明不足时才修改公共能力。
- 新增模板专项测试，覆盖库存、稳定 ID、目录容量、内容容量、分页、标题边界、图片矩阵、裁切、装饰保护、资源 Manifest、注册和回归。
- 测试音频、原生图表和参考动画没有进入生产 JSON。
- 测试非法图片数量、缺失源图尺寸和显式错误版式会显式失败。
- 不跳过测试、不降低断言、不隐藏错误。
- 所有完成、测试和验收结论必须基于当前执行链的新鲜证据。

十一、服务和真实 QA
- 操作服务前确认监听端口、PID、命令行、工作目录和项目归属。
- 保留健康实例，只启动或重启缺失、失败或受本次修改影响的最小服务集合。
- 归属不明的进程不得停止。
- 不使用会清理占用端口的统一启动方式处理已有健康服务。
- 使用真实 Worker 生成覆盖五种页面类型的作品。
- 验证文字编辑、保存重载、内容图替换、无图、失败重试和导出。
- 检查 1440×900、1280×720、768×1024、390×844 四种视口。
- 所有按钮必须有加载、成功、失败或明确假性交互反馈。
- 导出 PPTX 并重新导入，验证核心文字、内容图和装饰仍存在。
- /healthz 或单个 HTTP 200 不能单独证明完成；必须同时具备结构、测试和端到端证据。

十二、阶段推进
- 按 G0→G9 顺序执行，每阶段遵循“检查输入 → 实施 → 验证 → 记录证据”。
- G0～G8 连续推进，不等待逐阶段人工批准。
- 阶段检查不是人工门禁；每阶段满足自动检查后，自动确认结果为 PASS 并进入下一阶段。
- 测试失败、素材效果不佳、版式溢出和局部代码问题应先定位根因，再修复并重新验证。
- 不得通过跳过测试、降低断言、删除失败用例或隐藏错误继续推进。
- G9 全部自动检查通过后，自动确认进入 READY_FOR_CONFIRMATION，不为验收清单逐项请求人工批准。
- 长时间执行时至少每 60 秒提供一次有效进度，写明完成、验证、问题和下一步。

十三、自动边界处理
- 参考素材授权不明确时，自动使用原创或授权明确的替代素材。
- 没有真实 Logo、人物、内部数据或付费素材时，采用通用无 Logo、无真人设计，不生成假内容。
- 素材质量、Alpha 或体积不合格时重新生成、处理或压缩。
- 现有渲染器能满足需求时不修改渲染器。
- 与 Goal 无关的文件保持不变；扩大范围的需求记录为后续项。
- 提交、推送、PR、合并和部署不执行，也不阻断模板 Goal 达到 READY_FOR_CONFIRMATION。

十四、阻断规则
- 普通测试失败、素材效果不佳、版式溢出和局部兼容问题不构成阻断。
- 缺少必须由用户提供的授权素材或业务信息时，完成其他不受影响的工作后再报告。
- 需要不可逆操作、外部写入、生产动作或无关架构改造时暂停并请求授权。
- 只有同一阻断条件连续出现至少三个 Goal 回合，安全替代方案已耗尽，且没有其他范围内工作可继续时，才把 Goal 标记为 blocked。

十五、最终状态规则（唯一人工确认点）
- 必须完成模板文件、五项 MVP 素材、12 页 MVP、18 页生产版、语义标注、模板注册和专项测试。
- 必须完成目录容量、内容分页、图片隔离、裁切、无图和非法输入验证。
- 必须完成真实生成、编辑、换图、失败重试、四视口、PPTX 导出和重新导入。
- 必须保存素材来源、提示词、模型、截图、测试结果、失败记录和已知限制。
- G9 自动检测没有问题后，将文档状态更新为 READY_FOR_CONFIRMATION，并提交最终报告，请求人工确认。
- 除最终闭合外，不设置封面、素材、MVP、模板注册、测试或 QA 的人工确认门禁。
- READY_FOR_CONFIRMATION 不是完成状态；用户未明确确认前，不得执行闭合、调用 Goal 完成工具、标记 complete 或报告 DONE。
- 用户明确确认后，才允许执行闭合操作、调用 Goal 完成工具并报告 DONE。
- DONE_WITH_CONCERNS 只在用户明确接受已记录限制后使用。
- 提交、推送、PR、合并和部署保持未执行，除非用户另行单独授权。

阶段进度格式：
[阶段] Gx：阶段名称

- PPTX 导出和重新导入证据

- READY_FOR_CONFIRMATION 状态及用户确认请求

不得因为开发文档、素材、MVP、模板注册或部分测试完成，就声称整个模板开发已经完成。
