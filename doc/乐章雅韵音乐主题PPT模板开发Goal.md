## 2. 总 Goal

> 完成“乐章雅韵·音乐主题”PPT 模板的首版开发：交付 18 个可复用版式和 5 张正式装饰图，接入项目正常的模板选择、自动填充、在线编辑保存和 PPTX 导出流程，通过开发说明约定的验证，提供可检查的程序、样例、证据与使用说明，并在 T6 获得用户明确确认后完成闭合。

不纳入本 Goal：进度条、百分比柱、数据柱状图、地图、复杂关系图和原生表格的专用数据填充，以及动画、背景音乐迁移。Git 交付和生产操作不属于本次开发 Goal，按项目规则另行授权。

## 3. T1～T6 执行安排

T1～T6 用来组织工作和记录产物。T1～T5 不设置逐项人工审批，按实际输入和依赖自行安排，接口确认、素材准备与版式构建可以交叉进行；有可用页面就接入并检查，交付资料随开发整理。T6 自动检查和整理材料后统一提交用户确认；无需为每项另建实际 Goal。

| 任务 | 工作内容 | 交付产物 |
| --- | --- | --- |
| T1：确定版式与字段 | 核定编号、注册和填充接口、内容容量、封面与单图选版及结束页填充范围 | 实际编号和规则回填开发说明，版式有明确的触发条件 |
| T2：准备装饰素材 | 提取或制作 A1～A5，自动检查清晰度、透明效果和阅读区，整理正式资源 | 五张可用素材及来源、规格记录 |
| T3：构建模板页面 | 编写构建脚本，生成版式、可编辑原生元素、文字与图片槽 | 18 个版式、构建脚本、模板 JSON 和选择封面 |
| T4：接入生成与编辑 | 注册模板，接入选版、填充、分页、编号、图片关联、编辑保存与导出 | 正常项目流程可用，相关操作反馈正确 |
| T5：验证并修正 | 按开发说明第 6 节随开发检查，发现缺陷补充受影响失败测试，自动修复重验 | 当前候选的检查结果、必要截图和可编辑 PPTX 样例 |
| T6：整理交付 | 自动核对文件、引用及检查结果，准备可检查的程序与材料；通过后提交用户确认，明确确认后闭合 | 正式文件、样例、检查结果、使用说明和用户确认记录 |

T1～T5 根据实际产物和检查结果自动确认进度，回填开发说明后继续。结果可合并记录，不要求逐任务审批单；T6 自动检查通过后记录为“自动检查通过，待人工确认”，不能提前标为完成。用户确认只在 T6 最终闭合时进行。

## 4. 图片制作方式

**模板中需要的图片可以用 GPT2 图片模板生成。** 该制作方式保持可用；本次复用原稿合格装饰，未调用图片生成模型。

首版正式装饰仍为 A1 封面背景、A2 通用内容背景、A3 章节背景、A4 结束背景、A5 透明小提琴。尺寸、格式、构图与引用位置统一按开发说明第 4 节执行，不额外扩充素材库存。

- 背景和装饰不含标题、正文、编号、Logo、水印或业务数据；文字、简单边框和强调块保持原生可编辑。
- A5 使用真实透明通道。实际页面中的阅读区、清晰度、遮挡和透明效果合格后停止迭代。
- 原稿中合格素材可复用。记录实际使用来源和工具信息，不将未核实的底层模型写成已确认事实。
- 装饰标记为 `imageType: decoration`，业务图片标记为 `imageType: content`，换图不能覆盖固定装饰。

固定数据与 Fakes／Mocks 用于验证内容填充等程序行为，不排斥后续按本计划制作 A1～A5。素材制作与调用真实内容生成任务是不同工作，不能相互替代验证。

## 5. 自动确认与推进规则

1. **保持约定范围。** 优先复用现有协议和公共能力，只修复实际影响本模板的问题；不重新规划一套开发阶段。
2. **T1～T5 自动确认。** 编号、字号、容量、选版实现、素材是否可用及 T1～T5 进度按既定要求自行判断、记录并继续，不逐页、逐图、逐阶段询问。T6 检查自动执行，最终闭合等待用户明确确认。
3. **保护内容。** 原始标题、正文及项目顺序完整保留。长标题适配与正文分页分别处理；改变展示标题时保留 `sourceTitle` 并完整展示原题。
4. **检查随开发进行。** 按开发说明第 6 节自动检查内容、素材、编辑导出和受影响设备；结果合并记录。局部失败自动修复重验，其他独立工作继续，不设置统一停工等待的验收关卡。
5. **基于有效证据。** 记录候选代码版本、工作目录及检查结果；已通过且输入、实现和环境未变化的证据可复用。范围内失败必须修复，范围外问题记录为后续事项。
6. **用户参与范围。** 除 T6 最终确认外，仅在缺少必要输入、外部资源不可用且没有可行替代，或涉及授权范围外操作时说明具体需要。常规实现和质量判断不转为人工审批，真实失败不能自动标为通过。

文件位置沿用开发说明第 5.1 节。素材来源、样例及验证证据放在 `doc/assets/template_N_qa/`，不另设重复的报告或固定数量的审计文件。

## 6. T6 自动检查、人工确认与闭合

仅在 T6 设置一次最终人工确认，执行者先完成自动检查和可检查的交付准备，再请求用户确认：

1. 自动核对交付文件：18 个版式、5 张装饰图、构建脚本、选择封面、可编辑样例和使用说明。
2. 复用开发中的有效检查结果，确认正常流程和约定编辑导出功能已实现；未通过的部分自动修复重验，不重复已通过且未变化的检查。
3. 文件齐备、自动检查通过后，提交可检查的程序或访问方式、PPTX 样例、检查结果和使用说明，说明当前交付版本及实际限制。将 T6 记录为“自动检查通过，待人工确认”，T6 和总 Goal 均保持未完成。
4. 收到用户对当前交付版本的明确确认后，记录确认内容和所对应的版本，再将 T6 标为完成并完成总 Goal。用户未回复不能代替确认。
5. 用户反馈问题时，自动修复和完成受影响重验，重新提交确认；不增加其他阶段审批。

交付时汇报模板编号与名称、实现范围、关键文件、样例和验证结果，并说明实际限制。没有完成的项目明确列出，不把进度更新或任务中断作为完成结论。

人工确认用于本模板开发交付的最终闭合，不自动授权提交、推送、PR、合并或生产部署。
