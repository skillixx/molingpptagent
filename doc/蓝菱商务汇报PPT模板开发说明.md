开发默认遵循以下决策：

1. 只参考原稿的蓝色菱形视觉和页面关系，不复制原媒体。
2. V1 使用静态模板，不还原原生动画和页面切换。

G0～G9 都是自动检查点，不是逐阶段人工门禁。执行者通过检查后自动确认阶段结果为 `PASS` 并继续；失败时自动修复和重试。正常流程只保留从 `READY_FOR_CONFIRMATION` 到 `DONE` 的一次人工确认。

推荐实施顺序：

`预检 → 参考稿与权利审计 → 视觉规范 → 原创素材 → 12页MVP → 语义标注 → 接入测试 → 真实QA → 18页扩展 → 最终验收`

## 2. 模板目标和不做范围

### 2.1 开发目标

“蓝菱商务汇报”面向工作汇报、年度总结、项目复盘、经营分析、企业宣传和行动计划等通用商务场景。

生产模板应支持：

- 封面、目录、章节、内容和结束五种页面类型。
- 目录 2、3、4、5、6、10 项精确选版。
- 1～4 项纯文字内容精确选版。
- 无图、单图和双图内容。
- 超量项目和长正文无损分页。
- 内容图片由 Agent 填充或由用户替换。
- 无图输入时不出现空图片框、破图或异常留白。
- 生成结果可编辑、可保存、可导出 PPTX、可重新导入。

### 2.2 不做范围

- 不直接发布或分发参考 PPTX。
- 不复用授权范围不明的照片、地图、二维码、Logo、字体、音频和示例内容。
- 不承诺还原参考 PPT 的 PowerPoint 原生动画时间线。
- 不为单个模板重写 PPTX 导入器、PPTist 编辑器或公共渲染器。
- 不新增 PowerPoint 原生图表解析能力。
- 不内置真实人物、企业 Logo、产品界面、证书、业务数据和固定照片。

## 3. 参考稿结论与页面映射

### 3.1 关键结论

| 项目 | 结论 |
|---|---|
| 页面 | 40 页，16:9 |
| 结构 | 幻灯片没有可直接利用的结构化占位符 |
| 特殊对象 | 第 18、28 页包含原生图表；第 1 页包含音频 |

禁止从参考 PPTX 复制任何媒体字节到 `backend/main_api/template/`。

## 4. 视觉系统与安全区

### 4.1 设计语言

- 主题：蓝色菱形、轻量商务、点阵世界地图和克制的信息图。
- 语气：专业、清晰、可靠，不做科技大屏、金融终端或高饱和看板。
- 主视觉：用深蓝、亮蓝、浅蓝和白色菱形形成边缘层次，中心内容区保持安静。
- 页面节奏：封面和章节页强调几何主视觉，普通内容页降低装饰密度。
- 装饰位置：集中在左侧、底边和角落，不穿过标题、正文、数据或内容图片。

### 4.2 颜色

| 用途 | 色值 | 说明 |
|---|---|---|
| 主蓝 | `#0877C9` | 主标题、主编号和主要形状 |
| 深蓝 | `#0648A9` | 菱形层次、重要标题和对比强调 |
| 浅蓝 | `#93BCE8` | 次级菱形和弱层级结构 |
| 青色 | `#34A7C8` | 少量强调、箭头和辅助节点 |
| 主文字 | `#4B5158` | 标题和主要正文 |
| 次文字 | `#7B838C` | 说明和弱层级文字 |
| 主背景 | `#F4F6F9` | 普通页面背景 |
| 章节横幅 | `#D8DDE3` | 章节页半透明标题带 |
| 白色 | `#FFFFFF` | 菱形高光、图片留白和反白文字 |

红色只用于真实警告或负向语义。青色不得大面积替代主蓝，避免与现有科技类模板混淆。

### 4.3 字体和字号

| 层级 | 字体 | 最小字号 |
|---|---|---:|
| 封面标题 | 微软雅黑 Bold | 50px |
| 章节标题 | 微软雅黑 Bold | 44px |
| 页面标题 | 微软雅黑 Bold | 35px |
| 内容项标题 | 微软雅黑 Bold | 24px |
| 正文 | 微软雅黑 | 16px |
| 英文和数字 | Arial | 跟随对应层级 |
| 非核心说明 | 微软雅黑 | 14px |

自动缩字不得低于 12px。仍无法容纳时必须换用低密度版式或分页，不能截断正文。单行标题不得因内容替换变成两行。

### 4.4 画布和安全区

- 逻辑画布固定为 `1000 × 562.5`。
- 普通页面可编辑信息限制在 `x=64..936`、`y=42..516`。
- 内容页左右边距保持一致。
- 普通内容页的底部菱形装饰不得高于页面高度的 22%。
- 封面菱形主视觉可以占页面高度的 45%，但不得进入标题安全区。
- 点阵世界地图保持 6%～10% 的视觉不透明度。
- 章节数字、横幅和菱形装饰不得穿过标题。
- 内容图片槽必须验证横图、竖图和方图的居中裁切。

### 4.5 位图与可编辑元素边界

| 使用位图 | 使用 PPTist 可编辑元素 |
|---|---|
| 浅灰渐变背景和轻纸纹 | 目录编号、章节数字、页码和标题横幅 |
| 抽象低对比点阵世界地图 | 箭头、连接线、流程节点和时间轴 |
| 复杂的 2.5D 蓝色菱形集群 | 对比条、进度条、百分比圆环和简单数据图形 |
| 底边、角落菱形和局部柔光 | 卡片、分隔线、图片边框、蒙版和常规阴影 |

简单图标优先使用项目现有可编辑图标或授权明确的 SVG，不把整套信息图烘焙成图片。

## 5. 页面矩阵和选版规则

### 5.1 页面矩阵

| 页面类型 | MVP 数量 | 生产数量 | 稳定 ID |
|---|---:|---:|---|
| 封面 `cover` | 1 | 2 | `cover-diamond`、`cover-image` |
| 目录 `contents` | 6 | 6 | `contents-2/3/4/5/6/10` |
| 章节 `transition` | 1 | 2 | `transition-banner`、`transition-side` |
| 内容 `content` | 3 | 6 | `content-text-2/3/4`、`content-focus-1`、`content-image-1/2` |
| 结束 `end` | 1 | 2 | `end-diamond`、`end-action` |
| 合计 | 12 | 18 | MVP 通过后才能扩展生产版 |

MVP 先验证纯文字主链路。带图封面、第二章节、单结论、单图文、双图文和行动结束页在生产扩展阶段增加。

### 5.2 选版规则

1. 无内容图封面使用 `cover-diamond`；一张合法内容图使用 `cover-image`；两张及以上图片不得静默进入封面。
2. 目录 2、3、4、5、6、10 项精确匹配对应版式，其他数量无损分页。
3. 章节显式变体优先；未提供变体时按章节顺序稳定轮换两个章节版式。
4. 无图 1 项使用 `content-focus-1`；2～4 项使用对应纯文字版式。
5. 单图和双图分别使用 `content-image-1`、`content-image-2`。
6. 超量项目和长正文必须分页，保持字符、顺序和语义关联。
7. 带图长正文分页时，内容图只保留在首段，后续页使用纯文字版式。
8. 无图片输入时选择纯文字页，不保留空图片框或破图。
9. 图片数量、源图尺寸或显式版式不合法时返回明确的 `TemplateRenderError`。
10. V1 不使用原生图表页面，也不把未识别的图表数据强制塞入普通内容页。

- 不生成文字、数字、Logo、水印、二维码、人物、产品、界面或证据型图像。
- PNG 必须具有真实 Alpha 通道，不能用白底或棋盘格伪装透明。
- 不使用 Python 或其他程序化绘图方式生产位图装饰。
- 保存提示词、工具实际暴露的模型名称、原始输出、发布路径、压缩结果和人工检查记录。

## 7. PPTist 语义协议与动画策略

### 7.1 顶层要求

- 画布为 `1000 × 562.5`。
- 顶层包含 `id`、`title`、`width`、`height`、`theme`、`metadata` 和 `slides`。
- 页面 ID、元素 ID 和分组 ID 全局唯一。
- `metadata.mvpSlideIds` 精确列出 12 页 MVP。
- `metadata.productionSlideIds` 精确列出 18 页生产版。
- 图片使用 `/api/data/<filename>`，JSON 不内嵌 Base64 大图。
- 只有测试证明公共能力不足时才允许修改渲染器。

### 7.2 页面类型和文字槽

每页必须标注为 `cover`、`contents`、`transition`、`content` 或 `end`。

| 槽位 | 用途 |
|---|---|
| `title` | 页面主标题 |
| `content` | 副标题、章节说明或长正文 |
| `item` | 目录项或内容项正文 |
| `itemTitle` | 内容项标题 |
| `itemNumber` | 目录项或内容项编号 |
| `partNumber` | 章节编号 |
| `subtitle` | 图片说明或次级标题 |

同一内容组的编号、标题、正文和关联形状必须使用相同 `groupId`。内容不足时删除整个未使用组，不能留下孤立编号、连线、卡片或装饰。

### 7.3 图片槽

- 可替换业务图片使用 `imageType: "content"`。
- 背景和固定装饰使用 `imageType: "decoration"` 并锁定。
- 内容图片不得与背景、世界地图、菱形装饰或文字合并成一张图。
- 内容图片保持可选中和可替换，不得复用装饰元素的 `groupId`。
- 单图文和双图文版式必须声明严格图片数量约束。
- 无图片输入时移除整个内容图片槽。
- 内容图片必须携带原始宽高并按安全规则裁剪。

### 7.4 动画策略

V1 使用静态模板，不复用参考 PPT 的原生动画和页面切换。静态版必须先通过生成、编辑、导出和重新导入测试，不为了还原动画修改导入器或公共渲染器。

如后续需要动画，应单独制作非生产样张，只验证项目支持的淡入、滑入和缩放。任一关键环节丢失动画时，生产模板继续保持静态并记录限制。

## 9. 验证、验收和风险

### 9.1 自动化验证

专项测试至少覆盖：

- 12 页 MVP 和 18 页生产版库存。
- 画布、模板 ID、页面类型、稳定 ID、页面 ID 和元素 ID。
- 目录 2、3、4、5、6、10 项精确选版。
- 正文 1～4 项选版，以及 8 项和长正文无损分页。
- 封面、章节和内容标题边界。
- 0、1、2 张内容图片选版。
- 横图、竖图和方图裁剪。
- 非法图片数量、缺失源图尺寸等输入显式失败。
- 内容图片替换和装饰图片保护。
- 无图输入不出现破图、空框或异常留白。
- 原生图表、音频和参考动画未进入生产 JSON。
- 外置素材名称、格式、尺寸、Alpha、体积和引用完整性。
- 模板列表、JSON、封面、资源路由和现有模板回归。

```powershell
.\.venv\Scripts\python.exe -m pytest backend/main_api/tests/test_template_assets.py backend/main_api/tests/test_template_renderer.py
```

### 9.2 真实流程和设备检查

| 类别 | 必须验证的结果 |
|---|---|
| 生成与编辑 | 五种页面类型可生成；标题、正文、编号和数据可编辑并保存 |
| 图片 | 横图、竖图、方图裁剪正确；内容图可替换；装饰不被误换；无图不留空框 |
| PPTX 往返 | 导出并重新导入后，核心文字、内容图和装饰仍存在 |
| 设备 | 1440×900、1280×720、768×1024、390×844 均无横向溢出 |
| 交互 | 选择、生成、保存、换图、导出和失败重试均有加载、成功或失败反馈 |
| 视觉 | 18 页逐页检查，无重叠、裁切、异常换行、拉伸、破图和透明边缘问题 |

### 9.3 主要风险

| 风险 | 缓解措施 |
|---|---|
| 参考媒体授权未知 | 原媒体全部排除，只保留抽象构图关系 |
| 参考稿没有语义占位符 | 在 PPTist 中重建页面类型、文字槽、图片槽和 `groupId` |
| 原生动画与切换丢失 | V1 明确使用静态模板；动画另做非阻塞验证 |
| 导入后标题叠字和数字拆行 | 按项目画布重建文本框、字号、内边距和行高 |
| 内容图与装饰混组 | 严格隔离 `content` 与 `decoration`，不共享 `groupId` |
| 移动端操作不可达 | 四视口真实检查，所有按钮提供明确反馈 |

### 9.4 最终状态规则

只有在模板文件、素材、专项测试、受影响回归、真实生成、编辑、换图、设备适配和 PPTX 往返均取得新鲜证据，且 G9 自动检测没有问题后，才能进入 `READY_FOR_CONFIRMATION`。

进入 `READY_FOR_CONFIRMATION` 后必须等待人工明确确认。未收到“确认完成”或同等含义回复时，不得执行闭合、标记 `DONE` 或调用 Goal 完成工具。人工确认后，才可以闭合为 `DONE`；用户明确接受已知限制后，才可以闭合为 `DONE_WITH_CONCERNS`。
