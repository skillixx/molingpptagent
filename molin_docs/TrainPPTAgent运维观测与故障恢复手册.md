# TrainPPTAgent 运维观测与故障恢复手册

本文对应 T21/G4.5。它描述可观测契约、告警阈值和可逆恢复步骤，不代表生产环境已经部署或第三方依赖已真实通过。

## 1. 请求关联与安全日志

- 所有主 API 响应都带 `X-Request-Id`。合法调用方 ID 会被复用；非法或超长值会被替换。
- 未处理异常固定返回 `INTERNAL_ERROR`、中文安全文案、`retryable=true` 和同一个请求 ID；响应不包含异常正文。
- 写请求审计日志只包含 `event/request_id/user_id/method/path/status/outcome`。禁止记录 query、Cookie、Authorization、请求体、票据、模型提示词、对象存储地址或密钥。
- 结构化样例（全部为虚构值）：

```json
{"event":"mutation","request_id":"demo-request-001","user_id":1001,"method":"PATCH","path":"/presentations/demo","status":200,"outcome":"success"}
```

按请求 ID 排障时，只关联元数据和稳定错误码。不得临时开启请求体或认证头日志。

## 2. 健康检查与错误矩阵

| 场景 | 接口表现 | `retryable` | 运维动作 |
|---|---|---:|---|
| 进程存活 | `GET /healthz` 为 200 | - | 仅用于进程重启判断 |
| 必需依赖异常 | `GET /readyz` 为 503，依赖仅显示 `down` | - | 根据依赖名检查，不从响应猜测秘密配置 |
| 用户写入过频 | 429 `RATE_LIMITED`，含 `Retry-After` | true | 客户端退避；检查单用户异常流量 |
| 未处理异常 | 500 `INTERNAL_ERROR` | true | 用请求 ID 查安全错误日志 |
| 对象存储异常 | 503 稳定存储错误码 | true | 先只读检查 bucket，再恢复上传/删除租约 |
| Agent/PersonalDB 超时 | 业务稳定下游错误；`readyz` 对应依赖为 `down` | 依错误码 | 检查对应服务健康，不重复提交相同幂等键 |
| 数据库异常 | `readyz.database=down` | - | 摘流量、确认迁移版本与连接池，再恢复服务 |
| 墨灵异常 | `readyz.moling=down`（SSO启用时） | - | 保持计费关闭或停止收费任务，不伪造结算成功 |

`/readyz` 会检查数据库常量查询、对象存储只读 bucket、大纲/内容 Agent 卡片、PersonalDB 存活和启用 SSO 时的墨灵健康接口。异常正文、URL和凭证都不会回传。

## 3. 建议告警阈值

以下是首版保守默认值，正式上线前须根据实例数与基线流量调整：

- 可用性：连续 3 次（每 30 秒一次）`/healthz` 非 200，触发 P1 并重启单实例。
- 就绪性：`/readyz` 连续 2 分钟非 200，触发 P1；单依赖 `down` 连续 1 分钟触发 P2。
- 服务错误：5 分钟窗口内 5xx 比例大于 2% 且请求数不少于 50，触发 P1。
- 限流：单 owner 5 分钟内 429 超过 20 次触发 P2；全站 429 比例超过 5% 先核对容量与恶意流量，禁止直接取消限流。
- 任务恢复：`running` 超出租期或 dead-letter 数量增加即触发 P1；对账重试达到上限触发 P1。
- 存储：失败上传/删除租约持续 15 分钟，或用户配额账实不符，触发 P1。

## 4. 故障恢复顺序

1. 用只读检查确认异常进程、端口和项目归属；不得停止未知端口所有者。
2. 保存请求 ID、稳定错误码、时间窗口和依赖 `up/down`，不采集用户正文或密钥。
3. 先阻止新增收费任务；`BILLING_ENABLED` 保持 `false` 时不得把 Mock 响应当作平台验收。
4. 数据库先核对迁移头，再恢复应用；禁止应用启动时自动建表或越级迁移。
5. Worker 按租约和围栏令牌恢复；同一业务动作沿用原幂等键，不能人工改写终态。
6. 对象存储调用既有 stale-upload、stale-deletion 和未引用 checkpoint 恢复流程；先确认对象引用，再执行删除。
7. 恢复后依次验证 `/healthz`、`/readyz`、代表性只读接口、一个非收费幂等写请求，最后再解除摘流。

## 5. 回滚

- 代码回滚：恢复 T21 中间件、健康路由和配置变更后重启；不要回滚数据库迁移，因为 T21 未新增迁移。
- 配置回滚：开发/测试可关闭审计用于诊断，但生产必须保持 `RATE_LIMIT_ENABLED=true`。降低阈值或窗口要保留变更记录。
- 依赖降级：任何必需依赖 `down` 时保持实例不就绪；不得把 `required` 改为可选来伪造通过。
