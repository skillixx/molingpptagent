## 1. 总目标

在只修改 TrainPPTAgent、复用墨灵现有计费接口的前提下，完成以下闭环：

```text
资产入口票据绑定权益
  -> 服务端会话固化 entitlement_id
  -> 创建任务时冻结计费上下文
  -> reserve 预占 1 积分
  -> 生成成功后 settle
  -> 明确失败后 release
  -> 不确定结果进入 reconciliation
  -> 监控、审计、灰度和回滚
```

每个 Goal 都必须独立完成开发、验证、文档更新、一次 Git 提交和一次远程推送。一个 Goal 未通过门禁时，不得开始下一个 Goal。

## 4. 每个 Goal 的固定闭环

每个 Goal 严格执行以下顺序：

1. 读取本文件状态块、当前 Goal 卡、技术需求文档和最近一次 Git 记录。
2. 执行 `git status --short --branch`，识别并保留非当前任务修改。
3. 第一次执行时创建或切换到 `codex/trainppt-billing-closed-loop`；后续 Goal 沿用同一分支。
4. 将当前 Goal 标记为 `in_progress`，只实施该 Goal 范围。
5. 运行当前 Goal 的专项测试及必要的全量回归。
6. 把测试命令、结果、证据等级、遗留风险和下一 Goal 写入本文件“Goal 完成记录”。
7. 更新状态块：当前 Goal 标记 `completed`，`current_goal` 推进一项。
8. 只暂存当前 Goal 相关文件，检查 `git diff --cached` 和敏感信息。
9. 创建一个 Goal 级提交，提交格式为 `type(billing): BGxx 中文摘要`。
10. 推送当前分支到 `origin`，并用 `git rev-parse` 与远程引用核对提交一致。
11. 向用户输出阶段总结：完成内容、测试证据、提交哈希、远程分支、风险和下一 Goal。
12. 压缩上下文：以后续恢复只需读取“状态块 + 最近一条完成记录 + 当前 Goal 卡”为标准，随后自动继续下一 Goal。

若提交或推送失败，当前 Goal 保持 `verification` 或 `blocked`，不得标记完成，也不得进入下一 Goal。

## 6. Goal 卡

### BG01：固化资产级计费代码基线

目标：把当前工作区内已经实现并验证的资产级扣分修复整理为可审查、可迁移、可复现的远程代码基线。

范围：

- 从墨灵启动票据解析 `entitlement_id`，保存到服务端 Session；
- 创建 PPT 任务时冻结该权益，不允许回退到其他资产；
- 缺少权益时返回 `BILLING_ENTITLEMENT_REQUIRED` 并禁止生成；
- `entitlement_id`、`hold_id` 统一为正整数和数据库 `BigInteger`；
- settle/release 请求体发送 JSON number；
- 纳入 `20260730_0008` 迁移、受控真实 UAT 工具和自动化测试；
- 更新计费契约、环境模板和技术需求文档。

验证：专项测试、全量后端测试、`git diff --check`、迁移静态检查、敏感信息扫描。

Gate C1：全量测试通过；目标权益不会被其他权益替代；UAT 工具默认只读且真实写入上限不超过 3；当前改动已提交并推送远程分支。

不得做：应用生产迁移、打开生产计费、再次真实扣分、处理历史持有单或补偿历史误扣。

### BG02：迁移与配置演练

目标：证明新旧字段可以在生产同类型数据库上安全升级和回滚，且计费配置不完整时应用拒绝启动计费链路。

范围：

- 在隔离数据库副本执行 `0007 -> 0008 -> 0007 -> 0008`；
- 验证合法数字字符串无损转换；非法、零、负数和超范围数据阻止迁移；
- 验证启用计费时 SSO、持久化、Worker、商品、金额、平台地址和 Token 必须完整；
- 形成备份、迁移、回滚和数据审计命令清单，输出中不得包含秘密。

Gate C2：演练全程可复现；升级和降级验证通过；异常数据不会被静默丢弃；提交并推送远程。

不得做：连接生产数据库执行写迁移。

### BG03：本地闭环与故障恢复

目标：在本地可控环境证明每个生成任务只有一次预占和一个终态。

范围：

- 成功：reserve 后生成，结果持久化后 settle；
- 明确失败：使用原 `hold_id` release；
- 不确定：进入 `billing_pending`，由对账使用原动作收敛；
- 覆盖重复请求、双 Worker、进程重启、数据库提交失败、平台超时；
- 增加陈旧持有单、待对账量和失败计数的可观测性。

Gate C3：成功、失败、超时、并发和重启测试全部通过；无双预占、双结算或结算释放并存；提交并推送远程。

### BG04：非生产集成验收

目标：在不消耗生产积分的环境验证 TrainPPTAgent 与墨灵的完整协议。

范围：验证票据、权益查询、reserve、settle、release、余额不足、权益不归属、错误 Token、超时和 Worker 重启，并逐任务核对两边流水。

Gate C4：测试矩阵全部通过；无遗留活动持有单；每个任务可追溯；双方证据归档；提交并推送远程。

阻塞处理：没有可用非生产环境时，记录为外部阻塞，不得用 Mock 冒充 C4。

### BG05：生产预部署准备

目标：部署可运行代码、迁移和运维能力，但不产生新预占。

范围：生产备份、迁移前审计、执行迁移、部署 API/Worker、配置监控与告警、验证紧急开关和回滚路径，并保持 `BILLING_ENABLED=false`。

Gate C5：生产 API、Worker、对账和监控身份正确；迁移版本正确；计费仍关闭；回滚可执行；提交并推送远程。

人工授权：生产备份、迁移、部署、服务重启均须在执行前取得明确授权。缺少授权时将 BG05 标记 `blocked`，不得自动尝试。

### BG06：受控应用端真实 UAT

目标：从墨灵资产入口进入 TrainPPTAgent，通过真实生成任务验证扣分闭环，而不是只调用计费 UAT 工具。

范围：

1. 核对测试资产、用户、票据权益和授权积分上限；
2. 白名单开启，执行一次真实成功，确认只结算配置金额；
3. 执行一次可控失败，确认预占释放且已用不增加；
4. 执行一次可恢复异常，确认对账使用原持有单收敛；
5. 核对应用计费记录、墨灵持有单、权益前后余额和日志请求 ID。

Gate C6：三个场景证据完整；累计真实消费不超过本次授权；无新遗留持有单；错误权益零容忍；提交并推送远程。

人工授权：每次真实扣分测试前重新确认用户、资产、权益、单次金额和累计上限。此前“最多 3 积分”的授权不自动延续到新 Goal。

### BG07：灰度启用和最终验收

目标：在可观察、可停止、可恢复的条件下启用生产积分计费并关闭项目 Goal。

范围：白名单灰度、观察窗口、逐步扩大范围、用户错误提示验收、告警演练、停止新预占但继续终态处理的回滚演练，以及最终发布报告。

Gate C7：观察窗口内无重复扣分、错误权益或陈旧新持有单；成功率和积压达到发布阈值；业务、测试和运维验收；最终提交推送远程。

人工授权：打开生产计费、扩大灰度范围和全量启用均须逐次明确授权。

## 7. Git 同步规则

- 默认远程：`origin`。
- 默认开发分支：`codex/trainppt-billing-closed-loop`。
- 每个 Goal 恰好形成一个可审查的 Goal 级提交，并在完成时推送一次。
- 不使用 `git reset --hard`、`git checkout --`、`git clean`、强制推送或覆盖远程历史。
- 推送前必须拉取远程引用并检查是否出现他人提交；有冲突时停止并先解决，不覆盖。
- 只提交当前 Goal 文件；发现用户或其他任务的修改时保留并排除暂存。
- 不提交 `.env`、Token、Cookie、数据库连接串、真实票据、完整响应或含敏感信息的日志。
- Goal 总开发完成后再单独决定是否创建 Pull Request、合并到 `main` 和部署；阶段推送不等于已合并或已发布。
