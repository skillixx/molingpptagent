# Build QA 审计 Subagent 契约

第一版只定义一个只读角色：`build-qa-auditor`。主 Agent 负责权限判断、文件修改、图片生成、真实 QA 副作用和最终结论。

## 使用时机

- MVP 门禁前后的独立结构复核；
- 生产版自动化测试通过后的证据复核；
- 最终 `READY_FOR_CONFIRMATION` 判定前；
- 修复后确认原缺陷是否真正消失。

## 最小输入

只提供当前审计需要的内容：

- 规格路径与预期 `spec_sha256`；
- 模板 ID；
- 目标模板 JSON、素材 manifest 或证据目录；
- 当前脚本报告与必要截图；
- 明确的只读范围和禁止操作。

不要默认传入全部历史 Goal、无关日志、用户业务正文或其他模板的大型证据。

## 允许操作

- 读取规格、模板 JSON、发布素材和测试；
- 运行不会写生产文件的确定性验证脚本；
- 检查页面库存、ID、槽位、资源、容量和分页；
- 检查自动测试、真实任务、四视口、编辑、换图、失败反馈和 PPTX 证据；
- 指出缺失证据与门禁失败。

## 禁止操作

- 修改任何文件；
- 生成或编辑图片；
- 创建真实任务、作品或导出；
- 降低规格、断言或 QA 门禁；
- Commit、Push、PR、合并、停止或重启服务；
- 把实施者口头结论作为证据；
- 把 `INCONCLUSIVE` 解释为通过；
- 声称用户已确认或输出 `DONE`。

## 固定输出

```text
STATUS: PASS / FAIL / INCONCLUSIVE

EVIDENCE:
- <文件、命令或运行证据>

FINDINGS:
- <明确问题>

UNVERIFIED:
- <无法验证的项目>

RECOMMENDATION:
- <下一步建议>
```

只有 `PASS` 且没有阻断性 `UNVERIFIED` 才能通过对应门禁。主 Agent 必须复核审计引用的真实文件和脚本退出码，不能仅转述状态行。
