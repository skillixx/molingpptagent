# 测试与真实 QA 矩阵

本文件在 `test-only`、`run-qa`、`audit-evidence`，以及 `build` 的验证阶段读取。

## 自动化测试最低覆盖

### 结构与资源

- 模板 ID、标题、画布、页面库存和 MVP 标记；
- 页面 ID 与元素 ID 全局唯一；
- 页面类型和语义槽位；
- 引用集合与发布集合一致；
- 素材尺寸、模式、Alpha、体积和封面；
- 主 API 唯一注册、JSON 和封面响应。

### 选版、容量与分页

- 目录容量精确选版；
- 内容容量精确选版；
- 指标页或规格声明的专项版式可达；
- 0、1 和允许上限的内容图；
- 图片过量与尺寸缺失产生安全错误；
- 横图、竖图和方图裁切；
- 8 项以上分页不丢字、不乱序；
- 长正文拆页；
- 带图长正文的图片只出现一次；
- 装饰图片不被内容图替换；
- 双封面或其他声明变体可达。

### 回归范围

- 目标模板专项测试；
- `test_template_renderer.py`；
- `test_template_assets.py`；
- 当前受影响范围的后端测试。

只有修改前端源码时才强制运行前端类型检查、单测和生产构建；没有修改前端也必须做真实视口与按钮反馈 QA。

`run-template-tests.ps1` 只运行仓库中安全发现的 pytest 路径，不执行规格中的任意命令文本。测试失败时保留退出码和精简输出，不自动修复。

## 真实 QA 门禁

`run-qa` 必须获得明确授权。用真实持久 Worker 完成：

1. 模板列表只显示一个目标项。
2. 真实生成任务成功，覆盖规格声明的页面类型。
3. 编辑文字、保存并重新加载，修改仍存在。
4. 替换 `imageType: content` 图片，固定装饰数量与来源保持不变。
5. 制造或复用可控失败，界面显示错误，按钮恢复并可重试。
6. 桌面、笔记本、平板和手机四类视口无横向溢出。
7. 关键按钮可见、可触达，并显示加载、成功或失败反馈。
8. 运行时模板列表、JSON、封面和全部外置资源可访问。
9. PPTX 导出、解析、重新导入成功，重导入后仍可编辑。

推荐视口由规格提供；若规格未给出，不能凭历史尺寸自动声称四视口通过，应返回 `INCONCLUSIVE` 并补齐规格。

## 证据要求

每个门禁必须对应机器报告、截图、蒙太奇或可重放的运行摘要。只接受：

- 当前回合生成的新鲜测试结果；
- 真实任务状态与最小 ID 摘要；
- 视口尺寸、`clientWidth`、`scrollWidth` 和按钮状态；
- 编辑前后可验证值；
- 替换前后内容图与装饰摘要；
- PPTX SHA-256、页数、解析与重导入结论。

不接受实施 Agent 的口头“已通过”、旧截图替代当前状态，或仅以 `/healthz` 代表完整运行链路。

## 失败分类

- 测试断言或契约失败：`FAIL`，回到实现阶段。
- 依赖、Worker、浏览器或 API 不可用：`INCONCLUSIVE`，报告环境阻断。
- 证据缺失：`INCONCLUSIVE`，不得推断通过。
- 明确功能错误：`FAIL`；只有用户要求修复才进入 `repair`。

所有自动门禁通过后只能进入 `READY_FOR_CONFIRMATION`。
