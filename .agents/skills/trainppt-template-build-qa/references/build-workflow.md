# 构建与修复工作流

本文件只在 `build` 或 `repair` 模式读取。它定义阶段出口，不替代用户的实时授权。

## 输入契约

最低输入包括：

- 项目根目录；
- `doc/template_specs/<template-id>.yaml`；
- 当前用户明确授权的模式和副作用；
- 对应开发说明、Goal 与 QA 计划（如存在）。

规格必须为 `READY_FOR_BUILD`，且支持的 `spec_version` 为 `1`。开始和最终验收前都要对 UTF-8 无 BOM、LF 换行的规格原始字节计算 SHA-256；哈希不写回规格本身。

## 模式边界

### `build`

实现新模板。模板 ID 在注册、JSON、封面、素材和专项测试中任何一处已占用都应阻断，转回规划 Skill 重新分配 ID；不得覆盖已有模板。

### `repair`

仅修复已确认的验收缺陷。开始前记录失败证据、目标文件和允许修改范围。页面数量、视觉主题、版权策略、素材角色或 QA 标准发生实质变化时，不属于修复，必须更新规划规格。

## 阶段与出口

### 1. 开发预检

- 验证规格、哈希、参考文件和实时授权。
- 扫描工作区改动并标记目标文件是否与用户已有改动重叠。
- 从当前仓库发现模板目录、注册入口、renderer 和测试入口；不要依赖历史路径快照。
- 检查候选 ID 的全部冲突来源。

出口：没有契约、权限、漂移或覆盖风险。

### 2. 素材生产与审计

- 一项 manifest 对应一个独立提示词和一个可追踪发布文件。
- 背景与透明装饰分开生成。
- 记录工具真实暴露的信息；模型未暴露时写“未暴露”。
- 原图进入 `.codex-tmp/<template-id>/`，发布图进入当前模板目录。
- 达到规格重试上限仍不合格时进入 `BLOCKED`，不得无限付费重试。

出口：`audit-template-assets.py` 对已实现素材通过；无未授权 Logo、人物、付费资产、水印、伪文字或假截图。

### 3. MVP 构建

- 先实现规格定义的 MVP 页面，不假定固定页数。
- 页面和元素 ID 全局唯一。
- 文本、内容图片和装饰图片角色明确。
- 运行 JSON、素材、注册（若已接入）和模板专项测试。

出口：结构检查通过，真实持久 Worker 可以生成声明的 MVP 页面类型，内容和装饰角色不串用。

### 4. 生产版扩展与注册

- 仅在 MVP 真实门禁通过后扩展完整库存。
- 页面类型与数量精确匹配规格。
- 封面为真实可访问的 16:9 发布图片。
- 主 API 只出现一个目标模板注册项。

出口：JSON、素材、注册和模板 API 校验通过。

### 5. 自动化回归

- 运行目标模板专项测试、通用 renderer 与 assets 测试。
- 运行当前受影响范围的后端回归；修改前端时追加类型检查、单测和生产构建。
- 测试命令从当前仓库安全发现，不执行规格中任意 shell 文本。

出口：全部要求测试返回零；没有跳过、弱化断言或隐藏错误。

### 6. 真实 QA 与 PPTX 往返

按 [qa-matrix.md](qa-matrix.md) 生成真实任务证据。QA 运行只能创建测试任务、测试作品、临时导出和限定证据，不能借此修改生产代码。

出口：真实生成、编辑、换图、失败反馈、四视口、PPTX 解析与重导入均有可复查证据。

### 7. 证据与最终门禁

- 用 `collect-evidence.py --output doc/assets/<template-id>_qa/evidence.json` 汇总证据。
- 用 `verify-goal-gates.py` 独立判定。
- `build-qa-auditor` 只读复核真实文件和报告，不接受实施者口头结论。

出口：QA 为 `PASS`，实施状态为 `READY_FOR_CONFIRMATION`。Goal 仍等待用户确认。

## 停止并返回规划 Skill

以下变化不能由构建 Skill自行决定：

- 模板 ID 被占用；
- 参考文件哈希变化；
- 页面数、页面类型或视觉主题变化；
- 版权策略变化；
- 素材清单减少或角色改变；
- QA 门禁降低；
- 规格版本高于当前支持范围。

仅文件名规范化、压缩参数或不改变页面用途的实现微调可以记录为 `CHANGED` 后继续。
