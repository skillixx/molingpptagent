# 素材生成与发布策略

本文件在生成或审计图片素材时读取。

## 授权与成本门禁

- 只有用户当前请求明确授权实施且规格要求图片生成时才调用生成工具。
- `required_build_authorizations` 只是未来需求，不是当前授权凭证。
- 规格必须给出单项和全局重试上限；缺少上限时暂停，不允许无限付费重试。
- 达到上限仍不合格时保留失败摘要并进入 `BLOCKED`，不得用低质量图冒充正式素材。

## 生产原则

- 每项 manifest 使用独立提示词，输出角色、尺寸和安全区单一明确。
- 背景图与透明装饰分开生产，避免把整页 UI 或可编辑文字烘焙进图片。
- 不要求工具声称其没有暴露的模型标识；记录真实工具名称和“模型未暴露”。
- 禁止未经授权的 Logo、人物肖像、付费素材、伪文字、水印、假截图和第三方界面。
- 保留内容安全区，避免装饰覆盖标题、正文、页码和按钮。

## 文件与命名

- 发布文件使用 `<template-id>_asset_<role>_v<version>.<ext>`。
- 背景优先 JPEG/RGB；需要透明的装饰优先 PNG/RGBA。
- 原始生成图默认放入 `.codex-tmp/<template-id>/`，不进入 Git。
- 发布目录只保留 JSON 实际引用的素材。
- `evidence.json` 记录每个发布素材的相对路径、尺寸、模式、字节数、Alpha 范围和 SHA-256。

## Alpha 与边缘

- `alpha_required: true` 时，文件必须存在 Alpha 通道且至少包含部分透明像素。
- 全不透明 RGBA 不能冒充透明素材。
- 检查边缘残留、白底、黑边、锯齿和裁切缺口。
- 不自动抠图覆盖生成缺陷；若需要后处理，记录步骤与输出哈希。

## 尺寸与体积

以规格中每项素材的 `dimensions`、`format` 和 `max_bytes` 为准。不得把历史模板的尺寸或数量当作默认值。封面尺寸取规格 `template.cover`，应为可访问的 16:9 RGB JPEG。

## 审计

运行 `audit-template-assets.py` 检查：

- 引用集合与发布集合一致；
- 文件名安全且位于模板目录内；
- 尺寸、格式、模式、Alpha、体积与哈希；
- 封面存在且符合规格；
- 没有目标模板孤立素材。

审计通过只证明确定性属性，不替代人工视觉检查和版权判断。
